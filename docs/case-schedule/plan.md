需求卡已经锁定，但在写任何一行业务代码之前，依然必须执行**第二步：让 Agent 先交实施计划**。

课程表包含表格 DOM 构建、多节合并（`rowspan`）、单双周周次过滤与冲突检测，如果让 Agent 一口气生成几百行代码，一旦表格列宽错位或单双周计算出错，排查成本将成倍上升。

## 下达定计划指令

向 `pi` 下达明确的分解计划指令，强令其在写代码前先落盘 `TODO.md`：

```text title="定计划提示词"
先不要写 index.html！严格按五步循环来，现在执行【第二步：定计划】。

在项目根目录下生成 TODO.md，把实现拆成 3 个独立的小任务：
- 任务一：骨架搭建与基础网格（周次切换栏、5列6行基础表格、空网格样式与布局自适应）
- 任务二：课程数据接入与动态渲染（内置 COURSES 常量、根据当前周次过滤、rowspan 合并连续节次、单双周互斥展示）
- 任务三：冲突检测与周次持久化（冲突检测判定、表格内先录入者标红、上方警告栏展示全部冲突课程、localStorage 保存当前周次与异常回退）

每项任务需标明：改动文件、核心逻辑、手动验收步骤。
生成完后，在终端执行 git 提交，提交信息为 "docs: 建立三步实施计划"。
```

## 真实的 TODO.md 清单

Agent 随后在根目录下生成了规范详尽的 [TODO.md](file:///home/yoake/Code/schedule/TODO.md)（90 行），精确拆解为三个小任务：

```markdown title="TODO.md"
# 实施计划：课程表 Demo

单一交付文件 `index.html`（内联 CSS + JS），按顺序完成三个任务，每个任务结束后都能在浏览器中手动验收。

---

## 任务一：骨架搭建与基础网格

- **改动文件**：`index.html`（新建）
- **核心逻辑**：
  1. 页面三段结构：顶部周次切换栏（上一周 / 下一周按钮、第 N 周展示文案）、冲突警告栏（占位但初始 hidden）、课表网格容器。
  2. 原生 `<table>`，表头 5 列（周一至周五）+ 左侧 1 列节次标签（第 1–6 节）；`<tbody>` 生成 6 行 × 5 个空单元格，带有 `data-day` 与 `data-period` 标记。
  3. 周次切换基础逻辑：内存变量 `currentWeek`（初始 1），点击切周联动顶部文案并钳制在 1–20（到头禁用按钮）。暂不接入数据，网格恒为空。
  4. 样式：容器 `overflow-x: auto`，表格设置 `min-width: 640px` 与 `table-layout: fixed`，保证窄屏不塌陷、不重叠。
- **手动验收**：
  1. 双击 `index.html` 打开，无控制台报错、无网络请求。
  2. 首屏展示完整的 5×6 空表格，左侧节次标签与上方周列表头对齐。
  3. 初始显示「第 1 周 / 共 20 周」，上一周按钮禁用。点下一周数字递增，到 20 时下一周按钮禁用；点上一周可退回到 1。
  4. 拖窄浏览器窗口至 400px，表格出现横向滚动条，内容不破版。
  5. 刷新页面后回到第 1 周（本阶段不实现持久化）。

---

## 任务二：课程数据接入与动态渲染

- **改动文件**：`index.html`（增量脚本与卡片样式）
- **核心逻辑**：
  1. 注入需求卡中的 8 条 `COURSES` 常量数据。
  2. 过滤函数：输入当前周次 `W`，筛选有效课程（`all` 或当前周奇偶匹配）。
  3. 渲染主循环：重建 `<tbody>`。遍历 6 节 × 5 天，若当前格有课程且为开始节次，渲染带有课程名/教师/教室的卡片，并设置 `rowspan="span"`；被连续节次占用的后续单元格跳过不生成 `<td>`，保证每行总列宽恒等于 6。
  4. 切周联动：切换周次时清空并重新渲染表格。单双周课程交替呈现。
- **手动验收**：
  1. 第 1 周渲染出 6 个卡片位置（含单周课「操作系统」），周五第 1–2 节显示操作系统。
  2. 点下一周切到第 2 周，周五第 1–2 节切换为「计算机网络」，操作系统消失。
  3. 高等数学（周一 1–2 节）、线性代数（周二 3–4 节）等跨节课程纵向合并为 1 格，下方节次不错位、不破版。
  4. 检查元素确认表格每行单元格数与 rowspan 占位严格对应。

---

## 任务三：冲突检测与周次持久化

- **改动文件**：`index.html`（增量冲突判定算法与存储逻辑）
- **核心逻辑**：
  1. 冲突判定：两两比对当前周有效课程。满足「同 day + 节次区间重叠 + 周次交集」三条件判定为冲突。
  2. 冲突渲染：网格中保留先录入课程，所在单元格加上 `.is-conflict` 红色边框与标签；警告栏取消 `hidden`，输出所有冲突对详细信息。无冲突时警告栏隐藏。
  3. 周次持久化：`localStorage` 读写 `currentWeek`。读取时严格做 `1 <= W <= 20` 整数校验；读空、损坏或越界时静默回退为 1，不报错。
- **手动验收**：
  1. 第 1 周与第 2 周上方均弹出红色警告栏：明确列出「大学英语」与「编译原理」在周三第 1–2 节冲突。
  2. 网格周三第 1–2 节显示「大学英语」，卡片带有红色冲突高亮与标签；编译原理不进网格但数据未丢。
  3. 切到第 3 周并刷新页面，页面依然停留在第 3 周。
  4. 控制台执行 `localStorage.setItem('currentWeek', '999')` 刷新，页面安全回退到第 1 周，控制台零报错。
```
