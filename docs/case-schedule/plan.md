多文件项目的计划要说明文件职责和修改顺序。尤其要提前确定表格位置的数据结构，否则合并单元格时可能被迫重写整个渲染函数。

## 计划提示词

```text
读取 REQUIREMENT.md，包括字段表和八条验收标准。
现在不要写或修改代码，先输出：
1. 四个运行文件的职责和加载顺序
2. 十门课的数据数组
3. 不超过 6 步的实现顺序
4. 每一步修改哪些文件、页面出现什么变化、怎样验收
5. 哪一步最容易引起返工，前面要提前统一什么结构

首步就使用能支持 rowspan 的位置数据，避免先写一版再整体重写。
```

不要机械限制每一步必须少于多少行。首次骨架通常比后续修改多，关键是每步职责单一、可以独立验收。

## 推荐实施顺序

| 步骤 | 修改内容 | 可见结果与验收 |
| --- | --- | --- |
| 1 | 四个文件、十门课、`buildColumns` 和 `render` | 表格出现，连续课程已经合并；同格课程暂时只显示先录入者 |
| 2 | 周次过滤、切周按钮和本地保存 | 周三第 1 节随单双周切换，刷新保留周次 |
| 3 | 数据校验、冲突检测、标红和警告 | 周四冲突可见；非法课程被警告并跳过，不影响其他课程 |
| 4 | 窄屏样式和合法加课测试 | 375px 下表格容器滚动；只改 `data.js` 可加课 |
| 5 | 边界测试与 README | 八条功能验收和交付说明完整 |

第 1 步的 `buildColumns` 就返回五列、每列六个位置。每个位置可以是课程格、`null` 或 `'skip'`，后续只增加周次和冲突信息，不改变这张位置图的基本结构。

同格的线性代数、大学物理以及两门冲突课，使“未过滤时十门课全部同时显示”不适合作为首步验收。首步应检查十条数据完整、普通课程位置正确，已知同格情况留给后续步骤。

## 计划里要删掉和补上的内容

导出图片、拖动调课和详情弹窗都不在当前需求里。它们涉及额外的交互、兼容性和测试工作，应另开项目迭代，不需要用“必须引某个库”作为删除理由。

有两项保护要保留在计划中：非法字段和越界位置应给出警告并跳过；单双周判断集中在 `matchesWeek`，避免渲染和冲突检测各写一套规则。

## 保存 `TODO.md`

```markdown
# 课程表 TODO

需求和验收标准见 REQUIREMENT.md。

- [ ] 1. 四文件骨架、十门课、位置图和 rowspan 渲染
- [ ] 2. 单双周过滤、1–20 周切换和周次保存
- [ ] 3. 数据校验、冲突检测、标红与警告
- [ ] 4. 窄屏滚动和合法加课验收
- [ ] 5. 独立边界测试、README 和交付

每次只完成当前步骤，查看 diff，按对应标准验收后提交。
测试数据每次单独修改，验完恢复基准数据。
```

计划完成后进入 [四个生成步骤](/case-schedule/build/)。
