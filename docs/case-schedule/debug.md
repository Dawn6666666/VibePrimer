## Bug 1 · 加了周六的课，整页白屏

第 8 条标准是「加一门课只改 `data.js`」。你照着做，加了一门周六的选修：

```js
{ name: '合唱', teacher: '林', room: '音乐厅', day: 6, start: 1, span: 2, weeks: 'all' },
```

刷新。整页白，什么都没有。

::: warning 坏报告：没用
> 白屏了，怎么回事
:::

好报告四句话，和番茄钟那次一样：

```text
报告一个 bug：
1. 我做了什么：在 data.js 末尾加了一门 day: 6 的课，刷新
2. 我期待什么：周六出现（或者至少告诉我周六显示不了）
3. 实际发生什么：整页白屏，表格、按钮全没了
4. 报错原文：Cannot read properties of undefined (reading '0')，app.js 第 14 行
```

第 4 句是关键。打开控制台（F12 → Console），真的有这么一行。

原因：`DAYS` 只有 5 个元素，`cols[c.day - 1]` 就是 `cols[5]`，`undefined`。下一行 `col[s] = ...` 直接抛异常。**而这一行在 `for` 循环里，一次异常整张表都不画了。**

所以白屏不是"渲染坏了"，是"渲染第一步就死了"。这也是为什么你的页面会整体消失，而不是只丢一门课。

修法——数据是外部输入，代码不能假设它守规矩：

```js
for (const c of list) {
  const col = cols[c.day - 1];
  const s = c.start - 1;
  // 越界的数据跳过，不让它炸掉整张表
  if (!col || s < 0 || s + (c.span || 1) > PERIODS) {
    console.warn('这门课的位置不合法，已跳过：', c);
    continue;
  }
  …
}
```

加了 `console.warn` 而不是静默跳过，是为了让你下次能看见「它跳过了一门课」——**静默兜底是最难查的 bug 来源**。

::: tip 为什么这条值得单独讲
`day: 6` 是你的笔误，不是它的错。真实世界里错误数据永远存在——你自己录错的、从别处粘来的、版本升级后格式变了的。

**能扛住坏数据的一个功能，比功能多三个的版本可靠。**
:::

## Bug 2 · 合并之后，周四的课跑到周三去了

这条最像"灵异事件"。

| 实际看到 | 应该是 |
|---|---|
| 周三第 5 节：程序设计实验 | 周四第 5 节 |
| 周四第 5 节：空的 | 周四第 5 节：程序设计实验 |

一行里的第二个格子被吃掉了，后面的全都左移一格。

第一个念头一定是"`day` 写错了"。去 `data.js` 看：`day: 4`，没写错。

第二个念头是"`day - 1` 算错了"。也对，`4 - 1 = 3`，第四列（下标 3）——没错。

真正的原因在渲染循环里：

```js
if (cell === 'skip') {
  html += '<td class="empty"></td>';   // ← 错在这
  continue;
}
```

`skip` 的意思是「这一格被上面的格子用 `rowspan` 占了，**根本不存在**」。所以正确的写法是不输出任何 `<td>`：

```js
if (cell === 'skip') continue;
```

而你（或者你的 Agent）把 `skip` 当成了"空格子"来处理，多吐了一个 `<td>`。一个 `rowspan="2"` 的格子已经占了两个位置，再加一个空格子，这一行的格数就比表头多一个——浏览器把多余的那格挤到下一列，整行右移。

## Bug 3 · 单双周反了

第 1 周，周三第 1 节显示的是**大学物理**（双周课）。线性代数不见了。

你切到第 2 周，反过来了——第 2 周显示线性代数。

这个 bug 之所以能活到验收，是因为**两门课同一天同一节**，看起来"有那么一门课"，谁也没数它该是谁。只有拿原始课表逐门对（验收第 2、4 条），才会发现反了。

原因通常就两种，都很小：

```js
// 写法一：周次从 0 开始，靠 +1 显示
let week = 0;              // 内部 0
display.textContent = week + 1;   // 显示 1
// 于是 week % 2 === 0 的时候，显示的是「第 1 周」，被当成双周

// 写法二：干脆写反了
if (c.weeks === 'odd') return week % 2 === 0;   // 单周课在双周出现
```

修法不是"改一下 `% 2`"，而是**把所有单双周判断收到一个函数里，并且写清一句话**：

```js
// 第 1 周是单周。周次从 1 开始，不是 0。
function matchesWeek(c, week) {
  if (c.weeks === 'odd') return week % 2 === 1;
  if (c.weeks === 'even') return week % 2 === 0;
  return true;
}
```

然后加一条**能自己发现错**的检查——这是 [写测试](/craft/test/) 那一节的最小版本：

```js
// 在控制台里跑一下，别靠眼睛
console.table(
  COURSES.filter((c) => matchesWeek(c, 1)).map((c) => ({ 课: c.name, 周: c.weeks }))
);
```

第 1 周该出现的只有线性代数，第 2 周只有大学物理。跑一次，一秒确认。

## Bug 4 · 线性代数和大学物理同时变红了

冲突检测做完，周四那处冲突标红了。但也顺手把周三第 1 节标红了——**单周课和双周课互补，一次只有一门在上，这不算冲突。**

你的 `overlap` 大概是这么写的：

```js
if (a.weeks !== b.weeks) return false;   // ← 错
```

这句话的意思是"周次不一样就不冲突"：`'odd' !== 'even'` → 不冲突。看起来对。

问题出在 `'all'` 上：`'all'` 和 `'odd'` 也不相等，于是**每周都上的课和单周课被判成不冲突**——反过来错了。

正确的判断是「**只在两者都限定了具体周次、且不相同的时候，才不冲突**」：

```js
const bothLimited = a.weeks !== 'all' && b.weeks !== 'all';
if (bothLimited && a.weeks !== b.weeks) return false;
```

::: warning 这类 bug 的共同长相
它不在"有没有写"，而在"边界值对不对"。

`'all'` 是这里的边界值，`day: 6` 是 Bug 1 的边界值，`skip` 和 `null` 是 Bug 2 的边界值。**每个字段都有一个会让你翻车的特殊值**，找到它，单独测一遍。
:::

## 现在验第 7 条

窗口从右边慢慢拖窄，到手机宽度（大概 375px）停住：

| 看到什么 | 说明 |
|---|---|
| 表格横向滚动，页面本身不左右晃 | 对了 |
| 整个页面能左右拖，表头跟着跑 | `overflow-x: auto` 加在了 `table` 上，要加到外层 `div` 上 |
| 每一列挤成一列字，一格一个字 | 少了 `min-width`，表格被压扁了 |

正确的两句：

```css
.scroller { overflow-x: auto; }        /* 滚动的壳 */
table { min-width: 560px; }            /* 表格有底线，不能被压扁 */
```

一个管"能滚"，一个管"别压扁"。少一句都不行。

## 三次法则在这里怎么用

这四个 bug，每一个都是"发现 → 报告 → 修 → 验"一轮就完事。它们不难，难的是**看见**。

但如果你在某个 bug 上修到第三轮还没好——比如合并那个，你试了改下标、改循环、改 `span`，三次都不对——那就别改了：

```bash
git log --oneline
git restore .
```

回到上一次提交，重新描述问题。你已经知道了两件事：这个方向不对，以及这个 bug 长什么样。**带着这两件事重来，比在原地改第四遍快。**
