课程表比番茄钟更进一步：不仅界面更复杂，底层更依赖清晰的数据契约。每门课有 7 个核心字段，周次有单周/双周之分，节次有连续跨度，同一个时段还可能出现选课冲突。

如果在没有锁定数据结构之前就让 Agent 写界面，你往往会陷入“界面排版写好了，却发现单双周漏了字段”的返工泥潭。**第一步的铁律是：先定数据，再谈界面**。

## 让 Agent 先做技术访谈

在终端 `schedule` 目录下启动 `pi`，发送以下结构化访谈指令：

```text title="数据契约访谈提示词"
我要做一个本地课程表网页，双击 index.html 就能打开。
先不要写代码，也不要修改任何文件。
最多问我 8 个会影响实现的问题，一次列完。
只讨论课程字段、取值范围和数据使用规则，不讨论颜色与字体。
```

下面是 `pi` 智能体给出的 8 个关键问题与我们的确定性回答：

:::: chat title="课程表需求与数据访谈实录"

{Agent}

1. **课程字段集合**：你需要的字段是哪些？哪些是必填？是否需要学分、备注或课程编号？
2. **时间粒度**：按节次（第 1–N 节）还是按真实时刻（HH:MM）？一共几节？
3. **周次表达**：总共多少教学周（1–18？1–20？）？需要支持单双周吗？
4. **学期起点**：是否需要与真实公历日期挂钩计算？还是纯逻辑周次？
5. **上课日范围**：只支持周一到周五，还是周一到周日？
6. **连续跨度与冲突规则**：一门课能否占连续多节？同一时间出现两门课时怎样处理？
7. **数据存放方式**：这是单文件网页，如何规避 `file://` 下的跨域限制？
8. **视图与初始数据**：是否需要按周切换？初始数据量大概多少门课？

{.}

1. 7 个核心字段：`name`（课程名）、`teacher`（教师）、`room`（教室）、`day`（星期 1-5）、`start`（开始节 1-6）、`span`（连续节数 1-4）、`weeks`（'all' | 'odd' | 'even'）。不做多余字段。
2. 纯节次，周一至周五，每天 1–6 节。
3. 支持 1–20 周，手动上一周/下一周切换，单双周自动判断。
4. 不做公历日期绑定与自动计算，纯逻辑周次，保证确定性。
5. 仅周一至周五（1–5）。
6. 连续节次在表格中用 `rowspan` 合并；若同一时段冲突，表格保留先录入的课程并标红，表格上方警告栏列出全部冲突课程名与时段，不丢数据。
7. 单文件 `index.html`，CSS/JS 全内联，课程数据作为常量数组 `COURSES` 内联在脚本中，双击 `file://` 零网络请求、零 CORS 限制。当前周次用 `localStorage` 保存。
8. 顶部按钮切换 1–20 周；内置 8 门示例课（含每周、单双周各 1 门，以及 1 组真实冲突课）。

::::

## 课程数据字段契约

基于访谈确定的 7 个核心字段，建立不可破坏的数据契约：

:::: field-group

::: field name
@type string
@required
课程全称，例如 `"高等数学"`、`"数据结构"`。
:::

::: field teacher
@type string
@required
授课教师姓名，例如 `"张伟"`、`"李娜"`。
:::

::: field room
@type string
@required
上课教室或场地，例如 `"A101"`、`"体育馆"`。
:::

::: field day
@type number
@required
上课星期，取值范围 `1` 至 `5`（周一至周五）。
:::

::: field start
@type number
@required
课程开始节次，取值范围 `1` 至 `6`。
:::

::: field span
@type number
@required
连续上课节数，取值范围 `1` 至 `4`。约束：`start + span - 1 <= 6`，不可超出第 6 节。
:::

::: field weeks
@type string
@required
周次规则，仅支持 `'all'`（全周）、`'odd'`（单周/奇数周）、`'even'`（双周/偶数周）。
:::

::::

## 需求落盘：真实的 REQUIREMENT.md

Agent 在项目根目录下生成了规范的 [REQUIREMENT.md](file:///home/yoake/Code/schedule/REQUIREMENT.md)（93 行），清晰定义了边界、冲突判定规则与验收标准：

```markdown title="REQUIREMENT.md"
# 课程表 Demo 最简需求卡

## 1. 范围

| 项 | 决定 |
| --- | --- |
| 交付物 | 单个 `index.html`，CSS/JS 全内联 |
| 运行方式 | 双击以 `file://` 打开即可运行；零网络请求、零 CORS |
| 显示网格 | 周一至周五 × 第 1–6 节（5 列 × 6 行） |
| 周次 | 逻辑周次 1–20，手动上一周/下一周切换 |
| 日期绑定 | 不做。不读系统时间、不算"第几周"、不处理节假日 |
| 编辑能力 | 不做增删改界面。课表数据 = 内联常量，改课表即改代码 |
| 不做 | 导入/导出、多学期、账号、后端、构建步骤、第三方依赖 |

## 2. 数据契约

数据为 `index.html` 内的常量数组 `COURSES`，每项恰好 7 个字段：
name(string), teacher(string), room(string), day(1..5), start(1..6), span(1..4), weeks('all'|'odd'|'even')

约束：
- `start + span - 1 <= 6`，课程不得越出第 6 节。
- 星期超出 1–5、节次越界视为非法数据，不渲染该条。

## 3. 冲突与周次规则

**周次匹配**（当前周 W）：
- all：任意周都显示
- odd：W 为奇数时显示
- even：W 为偶数时显示

**冲突三条件判定**（两条课同时满足才算冲突）：
1. day 相同
2. 节次区间 [start, start+span-1] 有重叠
3. 周次规则存在交集（odd 与 even 永不冲突；all 与任意规则都相交）

**冲突处理**：
- 数据数组不删不改，冲突课一条不丢。
- 网格中该时段只渲染数组中靠前（先录入）的那条，并加红色标记。
- 表格上方警告栏列出全部冲突课程名与时段。
- 无冲突时警告栏隐藏。

## 4. 状态

- 当前周次 currentWeek 保存在 localStorage，取值钳制在 1–20，非法值自动回退为 1。

## 5. 内置示例数据（8 门）

| # | name | teacher | room | day | start | span | weeks |
|---|---|---|---|---|---|---|---|
| 1 | 高等数学 | 张伟 | A101 | 1 | 1 | 2 | all |
| 2 | 线性代数 | 李娜 | B203 | 2 | 3 | 2 | all |
| 3 | 大学英语 | 王芳 | C305 | 3 | 1 | 2 | all |
| 4 | 数据结构 | 刘强 | A204 | 4 | 3 | 2 | all |
| 5 | 操作系统 | 陈静 | B102 | 5 | 1 | 2 | odd |
| 6 | 计算机网络 | 赵磊 | C201 | 5 | 1 | 2 | even |
| 7 | 体育（羽毛球）| 孙鹏 | 体育馆 | 2 | 5 | 2 | all |
| 8 | 编译原理 | 周敏 | A305 | 3 | 1 | 2 | all |

说明：
- #5 与 #6 同天同节但 odd/even 互斥 → 演示单双周交替（不冲突）。
- #3 与 #8 同天同节且都是 all → 真实冲突组：#3 渲染并标红，#8 出现在警告栏。
```
