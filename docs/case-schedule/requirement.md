番茄钟的第一个问题是「它怎么动」。课程表的第一个问题是——**一门课要记哪些字段**。

这件事想不清楚，后面全白干。你会在写到一半的时候发现「单双周没地方放」，然后回去改数据、改渲染、改样式，一次改三处。这就是 [想清楚](/loop/think/) 里说的「需求漂移」，只不过它伪装成了技术问题。

所以这次的访谈，问的方向不一样：**不问界面长什么样，问数据长什么样。**

## 让它问你，但只问数据

在 `schedule` 文件夹里打开 Agent：

```text
我要做一个课程表网页，本地双击能打开，带一个数据文件。

先不要写代码。我要做的顺序是：先定数据结构，再定界面。
所以请只问和数据结构有关的问题：每门课需要记哪些字段、每个字段取值范围是什么。
最多 8 个问题，一次问完。不要问颜色、字体、动效。
```

::: chat title="数据访谈"

{.}

我要做一个课程表网页，本地双击能打开，带一个数据文件。先别写代码。先定数据结构，再定界面。只问和数据结构有关的问题，最多 8 个。

{Claude}

八个问题，都关于数据：

1. 一门课最少要记什么？我默认是：课程名、老师、地点、星期几、第几节。
2. 一节算多长时间？你学校一天几节？需要 1–12 节还是 1–6 节？
3. 连上两节、四节的课怎么存？存「开始节 + 结束节」，还是「开始节 + 连几节」？
4. 单双周的课怎么表示？有没有只上半学期的课（比如 1–8 周）？
5. 星期几用数字还是文字？数字的话 0 是周一还是周日？
6. 同一时间两门课，你想要它怎么办：报错、覆盖、还是都显示？
7. 要不要能增删改？还是直接改数据文件？
8. 怎么知道现在第几周？手动切、按开学日期算、还是不管？

{.}

1. 就这五个字段。不用记学分，不用记课程号。
2. 一天 6 节，1–6，每节两小节课连上算一节。
3. 存「开始节 + 连几节」。因为界面上一个格子跨几行，正好是这个数。
4. 只有单周、双周、每周三种。没有 1–8 周的课，别做。
5. 数字，1 到 5，1 是周一。别用 0，格子编号从 1 开始，我脑子对不上。
6. 都显示，但标红，上面再给一行文字提示。不要覆盖，覆盖了我就看不见我选错课了。
7. 不要编辑界面。改课一学期两次，直接改数据文件更快。
8. 手动切。用按钮，能记住上次看到第几周就行。

:::

八个问题，七个决定了实现方式。注意第 3 和第 6 ——**它们是 Agent 主动问出来的**，你没想过。

第 3 问你「开始节 + 结束节」还是「开始节 + 连几节」，你选了后者。这个选择直接决定了渲染代码里 `rowspan` 能不能直接用。选错的代价是每次渲染都要算 `end - start + 1`，多一个加法，多一个把 `+1` 忘了的机会。

## 需求卡

```md
# 课程表

## 谁用
我自己。大一下，一周十门课，课表在手机相册里是一张截图，看不清。

## 什么时候用
每天早上出门前看一眼今天几节课；选课的时候对照时间。

## 输入
不用输入。课程数据写在 data.js 里，我手动改。

## 输出
一张表：周一到周五五列，第 1 到 6 节六行。
连上的课合并成一格。单双周的课跟着周次变。
同一时间两门课标红，并给一行文字提示。

## 约束
- 双击 index.html 就能看，不需要服务器
- 数据在单独文件里，加一门课只改那一处
- 周次能切，刷新后记得
- 手机宽度下能横向滚动，不撑破页面
- 只用原生 HTML/CSS/JS，不用框架

## 不做什么
- 不做增删改界面
- 不做 1–8 周这种半学期的课
- 不做点格子弹详情
- 不接教务系统，不自动导入
- 不做暗色切换按钮（跟随系统就够）
```

## 数据结构定稿

写完需求卡，先别急着让 Agent 写界面。**让它把数据结构写出来，你审一遍。**

```js
// data.js
const COURSES = [
  { name: '高等数学 A(2)', teacher: '王', room: 'B203', day: 1, start: 1, span: 2, weeks: 'all' },
  { name: '线性代数', teacher: '孙', room: 'B101', day: 3, start: 1, span: 2, weeks: 'odd' },
  { name: '大学物理', teacher: '周', room: 'B101', day: 3, start: 1, span: 2, weeks: 'even' },
];
```

::: tip 这里为什么没有 export
因为要双击打开。`export` 配 `import` 属于 ES 模块，`file://` 下会被跨域策略拦掉，页面直接白屏，报的还是个和你的代码无关的 CORS 错误。

用普通 `<script>` 标签，`COURSES` 挂在全局，`app.js` 直接用。丑一点，能跑。
:::

七个字段，一个都不能少，也一个都不多：

| 字段 | 类型 | 取值范围 | 说错了会怎样 |
|---|---|---|---|
| `name` | 字符串 | 任意 | 显示成错的名字，肉眼可见 |
| `teacher` | 字符串 | 任意 | 跑错楼，肉眼不可见 |
| `room` | 字符串 | 任意 | 跑错楼，肉眼不可见 |
| `day` | 数字 | 1–5 | 课跑到别的天，格子错位 |
| `start` | 数字 | 1–6 | 课跑到别的节，格子错位 |
| `span` | 数字 | 1–6 | 合并不对，或撑破表格 |
| `weeks` | 字符串 | `all` / `odd` / `even` | 单双周反了，最阴的一种 |

::: warning 注意最后一行
`teacher` 和 `room` 写错了，页面一样好看，你也一样看不见——等你到了 B203 门口才发现课在 C105。

这也是为什么第七节要「逐门核对」：**数据类的错误不会自己跳出来，只能靠你对照原始课表看一遍。**
:::

## 三个决定，以及为什么

::: field-group

::: field 星期几为什么用数字 1–5，不用「周一」
@type string
@default day

因为要排序、要算列。`"周一" < "周三"` 这种字符串比较在 JavaScript 里能跑，但它靠的是 Unicode 运气，不是道理。

也不用 0–4。虽然数组下标是 0 起，但节次和课表格子编号都是 1 起，混着用一定会写出 `day - 1` 和 `day` 分不清的一天。**代价是每处都要写 `c.day - 1`，收益是你只要看到 `-1` 就知道这里在做「人话到下标」的翻译。**
:::

::: field 为什么存 start + span，不存 start + end
@type string
@default 渲染

因为 `rowspan` 要的就是「占几行」这个数。存 `end` 的话，渲染时要写 `end - start + 1`——那个 `+1` 是全世界最容易漏的加一。

存 `span` 的代价是：写数据的人要想「这门课连上几节」。这点成本在录数据时就付掉了，比在渲染代码里付三次强。
:::

::: field 单双周为什么用三个字符串值
@type string
@default weeks

因为真实需求只有三种：「每周都上」「单周上」「双周上」。用 `weeks: [1,3,5,7,9,11,13,15]` 这种数组也行，但它要你手写 8 个数字，写错一个没人发现。

代价是以后要加「1–8 周」的课时得改结构。那就以后再加——**第一版只解决第一版的问题**。
:::

:::

## 验收标准

需求卡写的是意图，这里写的是**你能一条条打勾的东西**。

| # | 标准 | 怎么验 |
|---|---|---|
| 1 | 打开是第 1 周，表头是周一至周五，左侧是 1–6 | 看一眼 |
| 2 | 十门课都在该在的格子里 | 拿原始课表逐门对，别扫一眼说"差不多" |
| 3 | 连上两节的课占一个格子，不是两个 | 看边框：一格跨两行 |
| 4 | 第 1 周第 3 节是线性代数，切到第 2 周同格是大学物理 | 点两下按钮 |
| 5 | 切到第 2 周，刷新页面，还是第 2 周 | F5 |
| 6 | 周四第 5 节出现冲突提示，两门课名字都在提示里 | 看右上角 |
| 7 | 窗口缩到手机宽度，表格横向滚动，页面不左右晃 | 拖窗口边缘 |
| 8 | 在 `data.js` 末尾加一门课，刷新就出现，别的文件不用动 | 真加一门试试 |

第 2 条和第 8 条是这次的重点。第 2 条逼你**逐条核对**，第 8 条验证**数据和界面真的分开了**。

::: tip 第 8 条怎么试最省事
随便加一门「形势与政策 · 周五 · 第 5 节 · 单周」，刷新。跳出来了，就说明结构是对的。

如果加完之后页面白屏——恭喜，你提前撞上了这一章第四节要讲的那个 bug（数据不全导致整表崩掉）。先记下来，别急着修。
:::
