课程表比番茄钟更进一步：界面更复杂，底层还依赖清晰的数据结构。每门课有 7 个核心字段，周次有单周/双周之分，节次有连续跨度，同一时段还可能出现选课冲突。

如果在确定数据结构前就开始写界面，很容易在后续发现遗漏字段而需要大面积修改。因此第一步的重点是先定数据，再谈界面。

## 课程数据的 7 个字段

访谈确定的数据结构非常直接，每门课程只保留以下 7 个字段：

- `name`：课程名称，例如“高等数学”。
- `teacher`：教师姓名，例如“张伟”。
- `room`：上课教室，例如“A101”。
- `day`：星期几，取值 1 至 5（代表周一到周五）。
- `start`：开始节次，取值 1 至 6。
- `span`：连续节数，取值 1 至 4（例如从第 1 节开始连上 2 节）。
- `weeks`：周次规则，取值为 `'all'`（每周）、`'odd'`（单周）或 `'even'`（双周）。

| **编辑能力** | 不做界面增删改 | 课表数据内联在代码常量中，改数据即改代码 |

### 2. 数据契约

数据为 `index.html` 内的常量数组 `COURSES`，每门课程包含以下 7 个核心字段：

```js
// 课程数据结构定义
{
  name: string,      // 课程名称（如 "高等数学"）
  teacher: string,   // 教师姓名（如 "张伟"）
  room: string,      // 教室（如 "A101"）
  day: number,       // 星期（1..5）
  start: number,     // 开始节次（1..6）
  span: number,      // 连续节数（1..4）
  weeks: string      // 周次规则（'all' | 'odd' | 'even'）
}
```

**字段约束**：
- 课程不得越出第 6 节：`start + span - 1 <= 6`。
- 星期超出 1–5、节次越界的记录视为非法数据，不予渲染。

### 3. 冲突与周次规则

**周次匹配（当前周 W）**：
- `all`：任意周均显示。
- `odd`：当前周 W 为奇数（单周）时显示。
- `even`：当前周 W 为偶数（双周）时显示。

**冲突三条件判定（两条课程必须同时满足以下三项才构成冲突）**：
1. **星期相同**：`day` 相同
2. **节次区间重叠**：`[start, start + span - 1]` 有重叠
3. **周次规则相交**：`odd` 与 `even` 互斥不相交，`all` 与任意规则均相交

**冲突处理方式**：
- **数据不丢**：数据数组不删不改，保留全部冲突记录。
- **网格展示**：同一时段在表格中只渲染靠前（先录入）的那门课，并加上红色边框与标签提示。
- **警告栏通报**：表格上方通报栏列出全部冲突课程名称与对应时段；无冲突时通报栏自动隐藏。

### 4. 状态

- 当前周次 `currentWeek` 存储于 `localStorage`，取值范围钳制在 1–20。
- 刷新或重新打开页面时保持在上次浏览的周次；读取到损坏或非法数据时安全回退至第 1 周。
