番茄钟交付完，它就是个练习。你不会真的每天用它。

课程表不一样——**这个项目有真实用途**。所以你这次交付的东西必须扛得住一件事：三个月后你自己回来加一门新课，还能改得动。

## 逐条过验收

<Gate group="schedule" />

上面的八条，每条都要手上试过。特别是第 2 条「数据在单独文件里，加一门课只改那一处」——那是这个项目能不能活过下学期的唯一标准。

## 边界测试：数据类的项目要多测一种东西

番茄钟测的是"点太快会怎样"。课程表测的是「**数据不对会怎样**」。

| 输入 | 期待 | 为什么值得测 |
|---|---|---|
| `COURSES = []` 空数组 | 表还在，全是空格子，不报错 | 新生第一周课表就是空的 |
| 一门课 `day: 6` | 跳过这门课，其余正常，控制台有一条 warn | Bug 1 |
| 一门课 `start: 5, span: 4` | 越界，跳过，表格不错位 | 第 5 节连 4 节 = 到第 8 节，超出 6 |
| 一课 `span: 0` 或没写 `span` | 当成 1 节 | 你手写数据时一定会漏 |
| 一课 `weeks: 'oddd'` | 当成每周 | 拼错一个字母不该毁掉整张表 |
| 同一格放 3 门课 | 提示 3 处冲突（或 2 对），不崩 | 循环要能处理多于 2 门 |
| 课名 20 个字 | 换行，不撑破格子 | 「毛泽东思想和中国特色社会主义理论体系概论」真的这么长 |
| 第 20 周点「下一周」 | 回到第 1 周 | 别停在 21 周，那里什么都没有 |
| 手机宽度 | 横向滚动，页面不左右晃 | 验收第 7 条 |
| 断网打开 | 完全正常 | 它本来就不联网 |

跑完这张表，你会发现前五条测的全是"**数据坏掉时你还能不能看**"。

这是数据类项目和有状态项目的最大区别。番茄钟的敌人是**时序**，课程表的敌人是**脏数据**。

::: tip 一条可以用一辈子的习惯
改完数据先看控制台。你的 `console.warn` 说跳过了哪门课，那就是你刚写错的那行。

看不见的兜底等于没有兜底。
:::

## README

````md
# 我的课程表

一个双击就能打开的课程表网页。数据在 `data.js` 里，改完刷新就生效。

## 怎么用
1. 双击 `index.html`
2. 点左上角 `‹` `›` 换周次，单双周的课会跟着变
3. 同一时间两门课会标红，右上角有提示

## 怎么加一门课
打开 `data.js`，在数组里加一行：

```js
{ name: '课程名', teacher: '老师', room: '教室', day: 3, start: 5, span: 2, weeks: 'odd' },
```

- `day`：1–5，周一到周五
- `start`：1–6，第几节开始
- `span`：连上几节，1 表示只上一节
- `weeks`：`'all'` 每周 / `'odd'` 单周 / `'even'` 双周

## 已知限制
- 只显示周一到周五，1–6 节。周末的课和晚上的课不显示
- 不支持「1–8 周」这种半学期的课，只能整学期单双周
- 数据写错（比如 day 写成 6）时，那门课会被跳过，控制台会提醒，页面上看不到
- 没有编辑界面。这是有意的，改数据文件更快

## 实现说明
- 原生 HTML/CSS/JS，无框架、无构建、无依赖
- 数据与渲染分离：`data.js` 只有数据，`app.js` 里的 `buildColumns()` 负责把数据算成表格位置
- 不联网，不上传任何数据
- 由 Claude Code 辅助生成，结构设计与测试由本人完成
````

::: warning 部署前想一下
真实课表里有老师的名字和你的上课地点。这不算敏感信息，但也没必要挂到公网让所有人搜到。

三种选择：
1. **只给自己用**：不部署，双击文件就行。最简单，也最合适。
2. **部署但改数据**：把老师改成「王老师」这类，教室改成一教/二教。
3. **部署真数据**：如果你就是想挂上去，至少别加学号和班级。
:::

## 部署

和番茄钟一样三条路，这里只补这个项目特有的坑。

::: code-tabs

@tab 压缩包

`index.html`、`style.css`、`data.js`、`app.js` 四个文件放进一个 zip，发给同学。

对方解压后双击 `index.html`。**四个文件必须放在同一层目录**——少一个就是白屏或者没样式。

@tab GitHub Pages

```bash
git add .
git commit -m "课程表 v1"
git push
```

仓库 Settings → Pages → 分支选 `main`，目录选 `/ (root)`。

因为四个文件都在根目录，不需要改任何路径。

@tab Vercel / Netlify

拖整个文件夹进去。不解压、不选文件，拖文件夹。

:::

部署完，在手机上打开那个链接看一眼。**这是这个项目的最后一条验收**：你在教室门口打开它，能不能三秒内看出下节课在哪。

## 换成你自己的课表

到这里为止，页面上还是我编的十门课。现在做这一步，只需要五分钟：

1. 打开教务系统，把你这学期的课表调出来
2. 在 `data.js` 里，一门一门改
3. 每改两门，刷新看一眼

改的时候你会遇到三个真实问题：

| 你遇到的 | 怎么办 |
|---|---|
| 教务系统写「1-16 周」，不是单双周 | 当成 `'all'` |
| 一门课一周上两次，时间不同 | 写两条记录，同一个课程名 |
| 连上三节的实验课 | `span: 3`，看看合并对不对 |

改完那一刻，你会发现一件事：**你开始关心 `data.js` 写得对不对，而不是页面好不好看。**

那就是这个项目变成你的了。

## 复盘

| 阶段 | 番茄钟 | 课程表 | 差在哪 |
|---|---|---|---|
| 想清楚 | 20 分钟 | 25 分钟 | 多花了 5 分钟定数据结构 |
| 定计划 | 12 分钟 | 15 分钟 | 多了一个"先写哪个文件"的决定 |
| 生成并运行 | 35 分钟 | 50 分钟 | 四条指令，每条的 diff 都要看 |
| 发现问题并修改 | 45 分钟 | 45 分钟 | bug 更阴，但找得更快 |
| 检查并交付 | 40 分钟 | 30 分钟 | 验收清单已经熟了 |
| **合计** | **2 小时 30 分** | **2 小时 45 分** | 真正"生成"的时间，两次都不到 5 分钟 |

看最后一行。两个项目加起来五个多小时，**AI 敲代码的时间不到十分钟**。剩下的时间你都在做同一件事：把"我想要什么"翻译成"什么算做完了"，然后验证它真的做到了。

这就是 [先把这个词说清楚](/start/what/) 里那句话的意思——需求分析是主线，生成代码不是终点。

## 自问三题

1. 如果现在让你给这个项目加一个「导出成图片」的功能，你要改哪几个文件？（答得出 = 你知道自己的项目长什么样）
2. 下学期的课表变了，你要花多久更新？（20 分钟以内 = 结构是对的）
3. 你现在能解释 `buildColumns` 里那两行 `-1` 吗？（能 = 这项目是你的）

第三个问题是我最想让你答出来的。**解释不了的东西不该留在你名下**——这是 Simon Willison 的规矩，也是你这两章唯一的硬要求。
