这一步确保项目具备真正的工程交付质量：完成 9 项全量基准验收、配置 `.gitignore` 保持工作区干净、并固化一条清晰可回溯的 Git 提交历史。

| # | 验收场景 | 操作方式 | 预期表现 | 实测结果 |

## 忽略过程截图与临时资源

在测试与交互过程中，浏览器或工具可能会在项目目录下产生快照截图（如 `task1-preview.png`、`task3-final.png`）。这些资产属于过程产物，不应混入代码版本库中。

让 Agent 创建 `.gitignore` 进行忽略：

:::: tabs

@tab 用户指令

```text title="收尾提示词"
在根目录下生成 .gitignore，写入 "*.png" 规则以忽略本地测试截图，提交信息为 "chore: 忽略本地截图"。
```

@tab Agent 执行日志

```bash title="收尾提交日志"
💻 [Bash]:
$ echo "*.png" > .gitignore && git add .gitignore && git commit -m "chore: 忽略本地截图"

📋 [Result]:
[main 40b0213] chore: 忽略本地截图
 1 file changed, 1 insertion(+)
 create mode 100644 .gitignore
```

::::

## 结对 CLI Agent 的实战复盘

回顾这次通过终端 `pi` CLI（结合 `tmux`）从零跑通课程表的全过程，核心收获如下：

:::: card title="CLI 编程智能体协作心得"
1. **终端即生产力**：不需要臃肿的 GUI 界面，通过 CLI + 非交互/交互模式，模型对文件读写、语法审查和终端命令的执行更直接、更纯粹。
2. **先定数据契约**：在多字段、多关联的复杂场景下，先把数据结构（7 个字段、取值范围、必填项）在需求卡中定死，后续编写 DOM 渲染时就不会左支右绌。
3. **架构防御优先**：在任务二实现 `rowspan` 时，Agent 主动选择了“先到先占、后到者进警告栏”的算法策略，保护了表格列宽不被错位撑爆。
4. **守住单任务边界**：每一步派发指令时严格声明“先不要做下一阶段的功能”，人类工程师始终掌握进度节奏。
::::
