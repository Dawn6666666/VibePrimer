课程表有真实使用价值，交付重点是数据能否维护、错误是否可见，以及别人能否按说明打开。部署可选，本地版也能完成验收。

## 功能验收

第二项要同时查看第 1、2 周，并区分“表格里的课程”和“警告里列出的冲突课程”。最后一项使用合法且不冲突的新课程；测试后删除，恢复自己的正式数据。

## 独立边界测试

下面每一行都是独立测试。只修改一项，记录结果后恢复基准数据，再测下一行。

| 测试数据或操作 | 预期结果 |
| --- | --- |
| `COURSES = []` | 表头和六个节次仍在，全部空格，不报错 |
| 一门课 `day: 6` | 跳过并警告，其他课程正常 |
| `start: 5, span: 4` | 因超出第 6 节而跳过并警告 |
| 漏写 `span` | 按 1 节处理 |
| `span: 0` | 作为非法数据跳过并警告 |
| `weeks: 'oddd'` | 作为非法数据跳过并警告 |
| 同时间、同周次放三门课 | 产生 3 对冲突，警告中能看到三门课名 |
| 课程名包含 `<` 或 `&` | 按普通文本显示，不生成 HTML 标签 |
| 第 20 周点下一周，第 1 周点上一周 | 分别回到第 1 周和第 20 周 |
| 本地文件断网打开 | 不使用外部资源时仍可显示 |
| 375px 视口 | 仅表格容器横向滚动，页面不整体溢出 |

非法 `weeks` 不能悄悄当作 `all`，否则显示和冲突函数可能对同一门课采用不同解释。统一校验能避免这类分歧。

## README 示例

````markdown
# 我的课程表

本地课程表网页，双击 index.html 使用。课程数据在 data.js。

## 使用
1. 点击 ‹ › 切换 1–20 周。
2. 单双周课程随周次变化，刷新后保留周次。
3. 冲突时，表格优先显示 data.js 中先录入的课程并标红。
4. 上方警告按课程对列出所有冲突，后录入课程不会因未占格而从数据中删除。

## 添加课程
在 data.js 的 COURSES 数组中添加：

```js
{ name: '课程名', teacher: '老师', room: '教室', day: 3, start: 5, span: 2, weeks: 'odd' },
```

- day：1–5，周一至周五
- start：1–6
- span：连续节数，且 start + span - 1 不超过 6
- weeks：all / odd / even

## 已知限制
- 只显示周一至周五、第 1–6 节。
- 不支持 1–16 周等起止周，需要扩展数据结构后再录入。
- 冲突课程不在同一格堆叠；先录入者占格，其余在警告中核对。
- 非法课程会跳过并在 Console 警告。
- 本地版不请求外部 API；部署后文件会存储在托管平台。

## 验证与 AI 使用说明
列出实际完成的八条验收和边界测试，并按事实说明 AI 与本人分工。
````

“本地版不请求外部 API”和“部署后数据已上传”是两件事。公开部署前，把姓名、教室、课程和周次组合当作可能暴露个人作息的信息处理，优先使用匿名示例数据。

## 部署方式

:::: code-tabs

@tab 压缩包

把 `index.html`、`style.css`、`data.js`、`app.js` 和 README 一起打包。四个运行文件必须保持原来的相对位置，解压后双击 `index.html` 验证。

@tab GitHub Pages

首次推送前先创建空仓库并配置 `origin`，完整命令见 [检查并交付](/loop/ship/)。之后进入 `Settings → Pages`，选择 Deploy from a branch、`main` 和 `/ (root)`，保存并等待部署。

部署后打开实际链接，检查四个文件是否都加载成功，再测切周和冲突提示。

@tab Netlify / Vercel

Netlify 可以使用官方支持的拖放部署或导入 Git 仓库。Vercel 通常导入 Git 仓库，也可以使用其 CLI。两者界面和构建要求不同，按各自官方流程操作，不要共用一句“把文件夹拖进去”。

::::

不部署时，部署相关检查标记为“不适用”，不需要为了打勾公开真实课表。

## 换成自己的课表

逐门修改 `data.js`，每改几门就刷新核对。常见情况这样处理：

| 原始课表情况 | 当前版本怎么处理 |
| --- | --- |
| 标注“1–16 周” | 不能直接写成 `all`；本版暂不支持，先记录为限制或扩展起止周 |
| 同一门课一周上两次 | 写两条记录，课程名可以相同 |
| 连上三节 | `span: 3`，确认不超过第 6 节 |
| 周末或第 6 节以后 | 当前版本无法显示，需要扩展 `DAYS` 或 `PERIODS` 并同步验收 |

全部替换后，再按原始课表核对一次。程序无法发现老师或教室录错，只能发现格式和位置不合法。

## 自查

1. 新增一门合法课程为什么只需要修改 `data.js`？
2. `day - 1` 和 `start - 1` 分别在做什么转换？
3. `null` 和 `'skip'` 为什么不能用同一种渲染方式？
4. 为什么 `all` 与 `odd` 会冲突，而 `odd` 与 `even` 不会？
5. 如果要支持 1–16 周，需要修改数据、校验、过滤、冲突和验收中的哪些部分？
