2025 年 2 月，Andrej Karpathy 在 [X 上的一篇帖子](https://x.com/karpathy/status/1886192184808149383)里提出 **vibe coding**。他描述的是一种很随意的写代码方式：说出想法，接受 AI 给出的代码，运行看看，出错就把报错贴回去，暂时不去细读代码。

这种用法适合周末试验和一次性演示。后来，Simon Willison 用 **vibe engineering** 指代更严谨的做法：AI 仍然参与生成代码，但开发者要审查、测试，并对结果负责。这两个说法目前没有严格的行业统一定义，放在一起看，主要是为了分清两种工作目标。

:::: card-grid cols="2"

<Card title="Vibe Coding 原始用法" icon="carbon:play-filled">

- 目标是尽快做出可演示的东西
- 可以暂时不读代码、不写测试
- 适合一次性项目、原型和试验

</Card>

<Card title="Vibe Engineering 工程化实践" icon="carbon:tools">

- 目标是做出能维护、能交付的软件
- AI 参与写代码，人负责需求、计划、审阅、测试和验收
- 每次改动都要知道原因和影响范围

</Card>

::::

这份指南采用后一种做法。小项目同样需要验收，只是流程可以轻一些。

## 你具体在做什么

你用自然语言描述意图，AI 生成代码草稿，你再检查草稿是否符合需求。要练好三项能力：

| 能力 | 具体是什么 | 练法 |
| --- | --- | --- |
| **表达** | 说清谁用、输入什么、输出什么、哪些事不做、怎样算完成 | 写需求卡，见 [想清楚](/loop/think/) |
| **验收** | 用实际操作和结果判断对错 | 每写一条需求，配一条可验证的标准 |
| **纠偏** | 发现偏差后，限制修改范围并重新验证 | 一次处理一条任务，验收后做一次 Git commit |

前两项不依赖某种编程语言。第三项需要你能读懂项目结构，并逐渐看懂关键代码。

## 为什么这门课的主线是需求分析

AI 可以在很短时间里生成几百行代码，也可能同时留下几个隐蔽错误。生成速度快，不代表结果正确，更不代表可以不读代码。

你需要先定义什么叫“对”，再设计操作去检查它。例如，“计时准确”很难直接验收；“开始后等待 5 秒，剩余时间约减少 5 秒”就能实际测试。语法和框架仍然要学，只是会围绕项目里的具体问题来学。

:::: tip 一个判断标准
如果你能说明程序接受什么、怎样处理、哪些情况会出错，还能指出每个文件的职责并独立完成验收，就已经在按工程化方式工作。

只会说“它能跑”，只能说明这一次运行没有暴露问题，还不足以交付。
::::

## 这份指南假设的起点

你可能写过 C 或 Java 的控制台作业，知道循环、数组和函数；也可能只照着教程改过 HTML，还没有做过带界面的完整项目。听说过 ChatGPT、Claude 或 Cursor，但没有让它们持续修改过一个项目，也很正常。

这份指南从安装工具开始，不要求你提前会 JavaScript、命令行或 Git。遇到新术语时，先理解它在当前项目里的作用，不必一次学完整套语言。

## 走完这份指南，你会有什么

  time=案例二 type=warning

  做出一个多文件课程表网页，练习数据结构、单双周、冲突检测和移动端适配。部署是可选步骤，本地版同样可以交付。

  time=查用手册 type=danger

  核心技能、常见问题、模板和延伸阅读可以按需查阅。第一次读不懂全部内容不影响继续做项目。

## 交付前守住三条底线

:::: warning 一、看不懂结构的项目先别交付
你不必立刻读懂每一行，但应能说出每个文件负责什么、数据从哪里来、结果在哪里显示。说不出来的部分，往往也是下次最难修改的部分。
::::

:::: warning 二、没有验收标准就先别写代码
“做个好看的”无法直接判断完成与否。开工前至少写下三条能当场试出来的标准，例如按钮点击后的行为、空输入时的提示、刷新后哪些数据保留。
::::

:::: warning 三、署名交付的内容由你负责
AI 生成的代码也可能出错。交作业、发给同学使用或上传到 GitHub 前，要检查功能、安全和课程对 AI 使用的要求，并如实说明 AI 参与了哪些工作。
::::

## 怎么用这份网站

左侧目录按学习顺序排列，时间紧时也可以按问题查阅。代码块右上角有复制按钮，提示词、需求卡和清单可以直接使用。页面里的按钮、滑块和清单可以操作，部分清单会把进度保存在你自己的浏览器里，不会上传。

第一次建议只读总览和当前要做的一节，遇到问题再回来查，不必先把整站背下来。准备好之后，点击下方「下一页」开始配置 VS Code。
