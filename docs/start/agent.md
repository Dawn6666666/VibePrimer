工具可以换，需求、审阅和验收的方法可以保留。先按自己的网络、费用和认证条件选一种，能实际读写项目文件即可，不必同时安装好几种。

## 编程 Agent 多了哪些能力

下面比较的是未连接项目的纯聊天页面和编程 Agent。网页产品如果提供文件上传、代码执行或 Agent 功能，也可能具备其中一些能力。

| | 未连接项目的聊天页面 | 编程 Agent |
| --- | --- | --- |
| 获取项目代码 | 通常由你复制粘贴 | 可以通过工具读取获准访问的文件 |
| 修改项目 | 通常由你复制回编辑器 | 可以在授权后修改文件 |
| 运行命令 | 取决于产品功能 | 可以安装依赖、运行测试并读取报错 |
| 出错后的处理 | 你补充报错和上下文 | 可以根据工具输出继续排查 |

使用 Agent 时，你负责限定任务、检查改动和验收结果。它能操作文件，也可能执行有副作用的命令，所以要先装好 [Git](/start/git/)，并留意工具的权限提示。

## 三条路线，按你的条件选

:::: card-grid cols="3"

<Card title="路线一 · 国内服务" icon="carbon:checkmark-outline">

**Trae 等带 Agent 的编辑器或插件**

中文界面和国内账号体系对初次配置比较友好。注册要求、可用模型和免费额度会调整，以产品官网为准。

**适合**：希望使用国内网络服务，想尽快开始练习。

</Card>

<Card title="路线二 · 学生认证" icon="carbon:education">

**GitHub Copilot**

符合条件的学生可以申请 GitHub Education 权益。是否包含 Copilot、包含哪个档位以及额度限制，以申请时的官方页面为准。

**适合**：已有或愿意申请 GitHub 学生认证。

</Card>

<Card title="路线三 · 终端工具" icon="carbon:rocket">

**Claude Code / Codex CLI**

在终端里读写项目、运行命令，适合练习计划模式、项目规则文件等用法。订阅、API 费用和可用地区因产品而异。

**适合**：已有可用账号，并愿意使用终端。

</Card>

::::

三条路线都能完成本指南。界面名称和快捷键可能不同，但“先给计划，等我确认后再改代码”这类指令都可以使用。

## 路线一：Trae 独立 IDE 或编辑器插件

Trae 提供独立 IDE。你可以直接使用它，也可以留在 VS Code 里选择其他 Agent 插件，两种形式不必同时安装。

::::: steps

1. **下载并登录**

   打开 [trae.cn](https://www.trae.cn/)，查看当前支持的平台、登录方式和额度说明，再按官方步骤安装。

2. **导入 VS Code 配置（可选）**

   如果独立 IDE 首次启动时提供导入选项，可以导入 VS Code 的设置和快捷键。没有该选项也不影响练习。

3. **打开项目文件夹**

   选择 `文件 → 打开文件夹`，打开具体项目，例如 `pomodoro`。不要只打开一个 HTML 文件。

4. **切到 Agent 模式**

   找到模式切换，选择 Builder / Agent 等可以修改文件的模式。纯 Chat 模式通常只给建议，不会直接改文件。

5. **做一个最小测试**

   ```text
   在当前文件夹新建 hello.html，里面只有一行 <h1>Agent 能改文件</h1>。
   不要修改其他文件。
   ```

   文件真实出现在文件树里，用浏览器打开后能看到标题，就说明读写链路已经可用。

:::::

:::: tip 留在 VS Code 里也可以
可以在扩展市场选择通义灵码等带 Agent 功能的插件，或使用开源的 Cline。Cline 插件本身开源，但连接模型 API 通常仍会产生费用，配置前要查看服务商价格。
::::

## 路线二：GitHub Copilot

::::: steps

1. 注册 GitHub，前往 [GitHub Education](https://education.github.com/) 查看并申请学生权益。学校邮箱只是常见验证方式之一，具体材料以官方要求为准。
2. 认证通过后，在账号权益页确认当前可用的 Copilot 档位和额度。
3. 在 VS Code 安装 **GitHub Copilot** 扩展并登录。
4. 打开 Copilot Chat，把模式切到 **Agent**，再用前面的 `hello.html` 任务测试文件修改。

:::::

学生资格和免费范围可能调整，不要把其他同学过去的截图当作当前承诺。遇到额度或权限问题，先查账号页面和官方说明。

## 路线三：Claude Code 或 Codex CLI

先按所选工具的官方安装文档完成安装和登录。然后在 VS Code 里打开具体项目文件夹，再打开内置终端，启动 `claude` 或 `codex`。这样终端默认就在项目目录里，不必再猜该 `cd` 到哪里。

以 Claude Code 为例，两个常用操作是：

- `Shift+Tab`：切换 Plan Mode 等模式。计划阶段可以先限制文件修改。
- `/clear`：清空当前会话。清空前要先把重要结论写入项目文件。

其他工具的快捷键和模式名称可能不同，请查看对应帮助。

:::: warning 控制按量计费的成本
订阅不一定包含 API 用量，也不一定能形成硬性消费上限。使用 API key 前，在服务商后台查看预算、额度和自动充值设置，限制单次任务规模，并定期查看用量。不要许可 Agent 无限制循环调用付费接口。
::::

## 装好后，先做这三件事

1. **在项目根目录启动。** 这能减少默认操作范围，但项目目录不是安全沙箱，Agent 仍可能通过命令访问其他位置，具体取决于工具和系统权限。
2. **先要求给计划。** 确认它理解了需求，再允许修改文件。计划模式也要以工具实际权限为准。
3. **动手前检查 Git。** 运行 `git status`，确认已有进度已提交或备份，便于核对和恢复。

## 别急着许可这些操作

| 操作 | 更稳妥的做法 |
| --- | --- |
| 一次修改多个互不相关的功能 | 拆成可以分别验收的小任务 |
| 安装你没核实的依赖 | 先查官方文档、包名和用途，确认确有需要 |
| 读取 `.env` 或粘贴密钥 | 提供 `.env.example` 和变量名，不给真实值；读取可能造成披露或日志留存 |
| 访问私人目录或学校内网 | 使用权限提示和命令审批，必要时用独立低权限环境 |
| 直接 push 到远程仓库 | 自己检查 diff、运行验收并 commit，再决定是否 push |

## 换工具时保留什么

每次换工具，都要重新确认权限、费用、规则文件和快捷键。可以继续使用的是同一份工作方法：写清需求，拆小任务，检查实际改动，独立运行验收，并记录尚未验证的部分。
