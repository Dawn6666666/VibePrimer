## 装不上怎么办

先看终端报错，再按常见问题排查。不要为了消除一条环境报错就盲目让 Agent 随意修改系统配置。

::: collapse
- `code .` 提示找不到命令

  - **Windows**：重新运行 VS Code 安装包，务必勾选“添加到 PATH”后重新安装。安装后必须关闭旧终端并打开新终端，才能读取新的 PATH 环境变量。
  - **macOS**：打开 VS Code，按快捷键 `Cmd+Shift+P` 呼出命令面板，输入并选择 **Shell Command: Install 'code' command in PATH**，按提示完成授权后重启终端。
  - **Linux**：确认已按上一节完成对应包的安装，在终端运行 `code --version` 查看是否有具体报错。

- `npm` 提示找不到命令

  通常是 Node.js 尚未安装，或者安装后未重新打开终端读取 PATH。请前往 [nodejs.org](https://nodejs.org/) 安装 LTS 版本，安装后彻底重启终端，运行 `node -v` 和 `npm -v` 进行验证。

- Agent 无法创建文件或提示没有权限

  依次检查以下三点：
  1. **打开路径**：是否通过“文件 → 打开文件夹”打开了整个项目文件夹，而非仅仅打开单个文件。
  2. **工作模式**：是否处于可以读写文件的 Agent 模式，而非仅能聊天的纯 Chat 模式。
  3. **终端目录**：VS Code 内置终端的当前工作路径是否位于项目根目录（可运行 `pwd` 检查）。

  若文件已生成但编辑器左侧树未更新，点击资源管理器顶部的“刷新”按钮查看。
:::

## 建一个实验文件夹

接下来的练习可以统一存放在一个父目录中：

- Windows 路径：`C:\dev\vibe-lab`
- macOS / Linux 路径：`~/dev/vibe-lab`

::: file-tree{title="实验父目录与项目结构"}
- vibe-lab/
  - pomodoro/     // 案例一，独立 Git 仓库
  - schedule/     // 案例二，独立 Git 仓库
  - notes.md      // 记录常见报错、解决方法与常用提示词
:::

这里有两个容易混淆的目录层级。`vibe-lab` 只是存放练习的父目录，不用执行 `git init`；`pomodoro` 和 `schedule` 才是各自的项目根目录。开始做某个项目时，用 VS Code 打开对应的项目文件夹，并在这个具体文件夹里初始化 Git、运行终端命令。

路径建议使用简单的英文字母、数字和连字符，减少跨平台脚本的兼容性问题。

## 先分清：命令到底在哪里运行

编辑器、终端和浏览器职责不同。看到教程里的代码块，先看代码标注的语言，再决定放到哪里执行。

::: tabs#runtime-env

@tab HTML#html

```html
<h1>我的第一个页面</h1>
```

在 VS Code 中新建 `hello.html`，粘贴内容并保存，再双击或拖拽到浏览器打开。不要把 HTML 代码直接贴进终端。

@tab 终端命令#bash

```bash
git status
```

在 VS Code 的内置终端里运行。它显示当前仓库的改动状态，不会在网页里生成内容。如果提示不是 Git 仓库，先检查当前目录是否正确。

@tab JavaScript#js

```javascript
console.log(2 + 3)
```

单行语句可以在浏览器控制台里即时运行查看结果。案例中的完整业务逻辑则需要保存到 `.js` 脚本文件中。

:::

## 一分钟验证：确认修改生效

通过以下三步确认编辑器、浏览器与终端处于联动状态：

::: steps

1. **修改并保存文件**
   把 `hello.html` 里的标题文字修改为 `<h1>这是我刚保存的页面</h1>`，按 `Ctrl+S`（macOS 为 `Cmd+S`）保存。

2. **在浏览器中刷新**
   切到浏览器按 `F5`（或 `Cmd+R`）刷新，确认能看到最新文字。如果没变，检查浏览器地址栏中的路径是否与当前编辑器打开的文件一致。

3. **在终端检查工作路径**
   在终端运行路径查看命令：
   - Linux / macOS / Git Bash：输入 `pwd`
   - Windows PowerShell：输入 `Get-Location`
   输出的路径应为当前练习所在的项目根目录。

:::

::: tip 页面没变化，先别急着让 Agent 改代码
修改未生效的常见原因通常是：文件未保存、浏览器未刷新、或者浏览器打开了另一处同名文件。先把这三项确认排除，再进入代码层面的排查。
:::

## 遇到阻碍时的备选方案

环境配置本身是开发的一部分，但不必在第一次练习时卡住所有进度：

- 如果某个命令行工具配置遇到困难，可以先使用图形化界面操作，或先使用单文件原生 HTML 完成前面的逻辑练习。
- 如果 GitHub 远程连接因网络问题受阻，先在本地执行 `git commit` 保存历史，稍后再配置远程推送。
