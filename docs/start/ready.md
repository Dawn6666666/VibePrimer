## 装不上怎么办

先看报错，再按下表排查。Agent 未必知道你电脑里实际安装了什么，不要为了消除一条环境报错就让它大范围修改项目。

:::: collapse

### 1. `code .` 提示找不到命令

Windows：重新运行安装包，把 **添加到 PATH** 勾上，安装后重开终端。旧终端不会自动读取新的 PATH。

macOS：在 VS Code 里按 `Cmd+Shift+P`，输入 `shell command`，选择 **Shell Command: Install 'code' command in PATH**。

Linux：确认安装已正常完成，并运行 `code --version` 查看具体报错。

### 2. `npm` 提示找不到命令

通常是 Node.js 没装，或者终端还没读取新的 PATH。去 [nodejs.org](https://nodejs.org/) 安装仍受支持的 LTS 版，重开终端后运行 `node -v` 和 `npm -v`。

macOS 已使用 Homebrew 的话，也可以运行 `brew install node`。Linux 可以参考 Node.js 官方发行版说明，避免随意复制来历不明的安装脚本。

### 3. Agent 建不了文件或提示没权限

依次检查三件事：

1. 是否用「打开文件夹」打开了整个项目，而不是单个文件。
2. 是否处于可以修改文件的 Agent 模式，而不是纯 Chat 模式。
3. 终端的当前目录是否为项目根目录。可以运行 `pwd`（Windows CMD 用 `cd`）查看，并检查工具的权限提示。

如果文件已经生成但文件树没更新，点击资源管理器的刷新按钮，再确认实际保存位置。

## 建一个实验文件夹

接下来的练习可以放在同一个父目录里：

```text
C:\dev\vibe-lab\          ← Windows 举例，macOS / Linux 可用 ~/dev/vibe-lab
├── pomodoro\             ← 案例一，独立 Git 仓库
├── schedule\             ← 案例二，独立 Git 仓库
└── notes.md              ← 记录报错、解决方法和常用提示词
```

这里有两个容易混淆的目录层级。`vibe-lab` 只是存放练习的父目录，不用执行 `git init`；`pomodoro` 和 `schedule` 才是各自的项目根目录。做某个项目时，用 VS Code 和 Agent 打开对应的项目文件夹，并在这个文件夹里初始化 Git、运行命令。

为了减少旧工具的兼容问题，路径可以优先使用简单的英文字母、数字和连字符。现代工具通常能处理中文和空格，不要遇到报错就只看路径，还要读取具体错误信息。

`notes.md` 可以记录“报错原文、原因、解决办法”。下次遇到同类问题时，这份笔记往往比重新搜索更快。

## 卡住时怎样换一条简单的路

:::: tip 先缩小问题，再继续做项目
环境配置本身也是开发工作的一部分，但不必在第一次练习时解决所有问题。如果同一个安装错误卡了很久，可以先记录报错，再换更简单的方案：用单文件 HTML 代替需要构建的项目，用图形化工具代替不熟悉的命令行。

GitHub 暂时不可用，可以只使用本地 Git；连本地 Git 也暂时不可用，可以先保留带日期的项目文件夹副本，之后再补做 Git 练习。普通文件副本不能替代提交历史，但能避免完全没有备份。
::::

## 现在可以开始做什么

环境通过后，你应该能用 VS Code 打开一个项目，让 Agent 在其中新建文件，并用 Git 保存一次可恢复的版本。后面的练习会继续使用这三项操作。

先读 [五步循环](/loop/) 总览，再进入案例一。其余四节可以在实际遇到对应问题时查阅，不必一次读完。
