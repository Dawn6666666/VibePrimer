一件事先说清楚：**Vibe Coding 不是许愿，是五个动作反复做。**

不是"我描述一下，AI 生成，我交作业"。是你在一个下午里，把这五个动作走上一圈、两圈、五圈，每一圈结束都有一个能跑的东西。AI 负责打字，你负责决定打什么、判断打得对不对、在它跑偏的时候把它拽回来。

这一章把五个动作拆开讲。后面两个案例，就是把这一章的东西完整走一遍给你看。

## 每一步的账

| 步骤 | 你在做什么 | 产出物 | 走完的标志 |
| --- | --- | --- | --- |
| **想清楚** | 说清谁用、解决什么问题、输入什么、输出什么、什么不做 | 半页需求卡 | 别人看完能用自己的话复述你要做什么 |
| **定计划** | 让 Agent 先读需求、给方案、拆任务，然后你否掉一半 | 3–7 条任务 | 每条任务都能单独跑起来、单独验收 |
| **生成并运行** | 一次一条任务，生成完立刻跑 | 能跑的版本 + 一条 commit | 你在屏幕/终端里亲眼看见了结果 |
| **发现问题并修改** | 复现、定位、改、再跑 | 修好的版本 + 一句原因记录 | 同样的操作不再出错，而且你知道为什么 |
| **检查并交付** | 按清单过一遍、写说明、交给别人 | README + 验收记录 | 别人照着你的说明能自己跑起来 |

## 为什么不能跳步

跳步不会立刻报错，它会在两小时后跟你要利息。三种最常见的死法：

::: collapse

### 跳过「想清楚」——需求在漂

你开口就是"帮我做个记账 app"。Agent 十分钟给你一个能加账单的页面。你觉得挺好，然后想起来：我要按周统计。加了。又想：我要能导入支付宝账单。加了。第三天你想起来最重要的一条——你是要**和室友一起记同一笔账**，单机版从第一步就选错了。

需求漂移不是 AI 的错。是你从没把"最终要什么"写下来过。

### 跳过「定计划」——一次性生成八百行

Agent 很听话，你说"做个课程表"，它一次给你 4 个文件、600 行代码，全对。问题是你看不懂，所以接下来任何一个改动，你都只能靠"再描述一遍，让它重写"。第二次重写时它顺手改掉了两个你没注意的地方，你也没发现。

大块生成不是效率，是把债推到明天。

### 跳过「检查」——演示前五分钟崩掉

本地跑得好好的，投屏到教室电脑上白屏。因为你的图片路径写的是 `C:/Users/你/Desktop/...`。或者更糟：你把带 API key 的 `.env` 一起传上了 GitHub，第二天收到额度用完的邮件。

交付不是"发个压缩包"，是"别人能自己跑起来"。

:::

## 一圈应该有多小

经验值，照着用：

- **一圈 30–60 分钟。** 超过一个半小时还没跑起来，说明任务拆大了，回去重拆。
- **一条任务一次 commit。** 一次 diff 超过 200 行就该警觉，超过 400 行基本等于没检查。
- **一次只改一件事。** 修 bug 的时候不要顺手加功能，加功能的时候不要顺手重构。

## 这一章的读法

后面五节，每节讲一步。每节都长这样：

1. **这一步到底在做什么** —— 一段话，不讲道理只讲动作
2. **产出物长什么样** —— 有完整示例，可以直接抄
3. **AI 在这里最容易怎么坑你** —— 具体到能认出来的程度
4. **一句话模板** —— 下次开口直接念

一次读完一章会很累。建议顺序：先读「想清楚」，然后去 [案例一](/case-timer/) 走一圈，卡住了再回来读对应的那节。

::: tip 不想按顺序读也行
如果你现在只是想赶紧把环境装好、让东西跑起来，去 [第 0 章](/start/what/)，装完再回来。装环境那章没有任何理论。
:::
