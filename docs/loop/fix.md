调试需要把现象变成线索，再用小实验验证原因。Agent 可以帮忙提出假设和修改代码，但你要提供真实操作、期望和结果，并独立复测。

## 固定四步

### 一、记录复现步骤

写清四项：

```text
操作：打开页面 → 开始 → 等 2 秒 → 暂停 → 继续
期望：从暂停的位置继续倒数
实际：重新从 25:00 开始
频率：连续三次都出现
```

稳定复现最容易定位。偶发问题也可以修，只是要先记录发生时间、输入、浏览器、日志和相关操作，寻找共同条件，不要假装它每次都必然出现。

### 二、读报错和调用位置

浏览器按 `F12` 打开 Console，终端报错则向上找到第一段相关错误。

```text
Uncaught TypeError: Cannot read properties of null (reading 'textContent')
    at renderTimer (script.js:42:18)
    at script.js:51:3
```

第一行说明某个值为 `null`，代码却尝试读取它的 `textContent`。`script.js:42` 是异常暴露的位置，可以从这里开始检查，再追溯这个值在哪里赋值。可能是元素 id 拼错，也可能是脚本执行时元素还不存在，不能直接断定第 42 行就是唯一根因。

调用链里的 `at ...` 表示函数怎样一路执行到这里。先看自己的文件，再看第三方库。

### 三、安全地缩小范围

可以先备份或创建 WIP 提交，再选择一种方法：

- 回到上一个能运行的提交，分批恢复改动，找出引入问题的那一处。
- 换一个输入、浏览器或运行方式，比较结果差异。
- 对能够独立拆分的代码做二分排查。不要随意注释互相依赖的半段代码，以免制造新的语法和引用错误。

二分排查能缩小范围，但不保证在固定次数内找到原因。异步、时序和环境问题还需要日志与对照实验。

### 四、一次验证一个假设

```text
假设：暂停时没有执行 clearInterval，所以旧定时器仍在运行。
验证：在计划调用 clearInterval 的分支记录日志，并检查进入分支的条件。
结果：日志没有出现。接着确认是分支没进入，还是日志被 Console 过滤。
```

一次只修改与当前假设有关的内容。修好后还要复测相关功能，避免一个问题消失，另一个功能被破坏。

## 让 Agent 先诊断

```text
先不要改代码。
把下面信息分成“已确认事实”和“待验证假设”。
列出最可能的三个原因，每个原因给一步最小验证操作。
不要只凭报错猜结论。
```

这样你能先排除方向，再让它做有针对性的修改。即使它给出的排序不合理，验证结果也会提供新线索。

## 连续三次修改仍没好

三次不是硬性定律，而是一个提醒：你们可能一直在验证同一个错误假设。先保存失败结论，不要继续在旧补丁上叠加修改。

如果最近的提交已经包含坏代码，可以从最后一个好提交新建分支，保留原分支供对照：

```bash
git status
git log --oneline
git switch -c retry-fix <好提交的哈希>
```

执行前确保未提交改动已经提交或备份。新分支用于重新尝试，不会删除原分支历史。不要为了省事直接对含有未保存工作的分支执行 `git reset --hard`。

新会话开始时，让它读取 `REQUIREMENT.md`、`TODO.md` 和已经排除的原因，再继续诊断。

## 常见报错速查

| 看到这个 | 可能原因 | 先做什么 |
| --- | --- | --- |
| `Cannot read properties of undefined/null` | 变量或元素没有预期值 | 检查赋值来源、元素 id、数组是否为空 |
| `xxx is not a function` | 调用的值不是函数 | 检查拼写、作用域和实际类型 |
| `404 Not Found` | 请求地址不存在或部署路径不正确 | 在 Network 中核对 URL、大小写和响应 |
| `Blocked by CORS policy` | 浏览器拦截跨域读取 | 本地页面通过 HTTP 服务打开；接口跨域由后端正确配置允许来源 |
| `NaN` | 数字运算混入了非数字 | 打印并检查每个参与运算的值 |
| `Unexpected token '<'` | JS / JSON 请求收到了 HTML | 检查请求地址和实际响应 |
| 页面空白且 Console 无报错 | 渲染条件未满足，或逻辑提前返回 | 从入口开始检查数据和分支 |
| 修改后页面没变 | 未保存、缓存或打开了另一个地址 | 确认文件与 URL，再硬刷新 |

使用 `file://` 双击页面时，相对路径也不能绕过所有浏览器限制。遇到模块加载或请求问题，用 Live Server 或 `python3 -m http.server` 提供本地 HTTP 服务。

## 修好以后记录原因

在 `BUGS.md` 里写一条简短记录：

```markdown
## 暂停后仍然计时
- 现象：暂停后数字继续减少
- 原因：重复启动创建了第二个定时器，暂停只清除了后一个
- 修复：启动前检查运行状态，并统一由一个函数更新按钮和定时器
- 复测：开始、暂停、继续各三次，速度不变，暂停时数字不动
```

记录“怎样知道修好了”和“为什么出错”，比只记一句“已修复”更有用。以后遇到相似现象，可以先查这份日志。

问题修复并通过相关复测后，进入 [检查并交付](/loop/ship/)。
