这一步要把“我想要”写成可以开发、可以验收的需求。Agent 可能不追问，而是直接采用自己的假设。假设一旦变成代码，后面修改的成本就会增加。

## 写一张需求卡

先用半页纸回答下面六个问题。初版不必写得很长，但不能只留下一个产品名称。

:::: field-group

::: field 谁用
@type 具体的人
@required
例如自己在宿舍用笔记本，或者班级同学用手机查看。不同使用者会影响设备支持、数据共享和隐私要求。
:::

::: field 什么时候用
@type 场景和频率
@required
每天晚上复盘和每学期开学填一次需要保存的数据、提醒方式和操作流程都不同。
:::

::: field 输入是什么
@type 数据或操作
@required
用户要输入文字、上传文件，还是只点击按钮？哪些输入可以为空，格式有没有限制？
:::

::: field 输出是什么
@type 可观察的结果
@required
屏幕上显示什么，文件里保存什么，刷新或重新打开后哪些内容还在。
:::

::: field 约束
@type 必须满足的条件
@required
运行设备、是否联网、能否安装依赖、交付时间，以及不能上传哪些数据。
:::

::: field 不做什么
@type 本版排除项
@required
明确本版不做的功能，防止 Agent 根据常见产品形态自行添加登录、分享或统计。
:::

::::

需求卡还需要一组验收标准，用来说明怎样算做完。

## 同一个番茄钟，两种写法

:::: flex between gap="20"

<Card title="难以验收" icon="carbon:close-outline">

> 帮我做一个好看的番茄钟，界面要现代，计时准确，最好有点动画。

好看和现代没有说明判断标准，计时准确也没有给出测试方法。Agent 可以交付很多版本，但你很难说明哪一版符合要求。

</Card>

<Card title="可以直接测试" icon="carbon:checkmark-outline">

> 做一个本地单文件番茄钟，双击 index.html 就能用。初始显示 25:00，提供开始/暂停/继续和重置。归零后显示 00:00，页面标题变成休息一下。刷新或重新打开时倒计时回到 25:00，今日完成数保留。不要声音、登录、后端和多语言。

</Card>

::::

第二种写法仍有视觉设计空间，但核心行为和完成条件已经明确。

## 验收标准怎么写

验收标准要能从界面、声音、文件、日志或程序输出中观察，并且能判定通过或不通过。

| 模糊写法 | 可测试的写法 |
| --- | --- |
| 界面要好看 | 视口宽度 375px 时，两个按钮不重叠，页面没有意外横向滚动 |
| 计时准确 | 用秒表记录 60 秒，页面剩余时间也约减少 60 秒，误差不超过 1 秒 |
| 数据不能丢 | 新增一条记录后刷新并重新打开浏览器，该记录仍存在 |
| 要有提示 | 输入为空时点击提交，按钮下方显示写点什么 |
| 性能要好 | 在指定设备和 30 条数据下测试，首屏在 1 秒内出现，滚动无明显卡顿 |

最后一行仍然包含一定主观判断，所以进一步测试时应写明设备、数据量和测量方法。第一个案例暂时不需要性能指标。

测试长时间行为时，可以增加一个明确的测试配置。例如把番茄钟的 `TOTAL` 暂时改为 `5`，验证归零和计数后立即恢复为 `25 * 60`。不要把测试用的 5 秒留在交付版里。

## 试着把一句愿望改成测试

假设你对 Agent 说暂停后不要乱跑，它需要知道你指的是数字、按钮，还是页面布局。先自己补上操作和结果，再展开参考。

::: details 参考：暂停怎样才算通过

```text
打开页面，点击开始，等待约 3 秒后暂停。
记下此时的剩余时间，再等 5 秒，显示应保持不变。
点击继续，数字应从记下的时间继续减少，不回到 25:00。
```

这条测试分别检查暂停和继续。只看到按钮文字变成继续，还不能证明计时真的停止了。

:::

## 让 Agent 帮你找遗漏

你不必独自想全所有问题，可以让 Agent 先做需求访谈。

:::: chat title="编程 Agent"

{.}

我要做一个番茄钟网页，本地双击就能用。先别写代码。最多问我 10 个会影响实现的问题，一次列完，不要问配色。

{Agent}

1. 25 分钟固定，还是允许修改？
2. 一轮结束后自动开始休息，还是等待用户操作？
3. 归零时用声音、标题变化，还是其他提示？
4. 是否记录今日完成数？重新打开后要保留吗？
5. 计时中关闭页面，重新打开时继续、暂停还是重置？
6. 只在电脑上用，还是也要适配手机？
7. 需要暂停后继续吗？
8. 归零后停留 00:00，还是立即开始下一轮？
9. 需要进度条或圆环吗？
10. 使用单个 HTML 文件，还是拆分 HTML、CSS 和 JavaScript？

::::

回答问题后，把决定写进需求卡。访谈记录不能代替需求卡，因为它通常同时包含被否决的方案。

## 本版不做什么

番茄钟第一版可以明确排除：

- 登录、账号和云同步
- 多语言和主题切换
- 任务清单和数据导出
- 自定义时长和休息倒计时
- 框架、构建工具和外部依赖

排除项不是永久承诺。以后确实需要时，可以另开一轮需求分析，而不是让 Agent 在当前任务里顺手加入。

## 想不清楚时怎么办

可以找一个熟悉的产品，说明只想借用它哪一项行为、哪些地方不要。也可以先写排除项，再描述最小版本：“如果只能保留一个核心操作，用户必须能完成什么？”

## 可复制模板

```text
我要做一个【什么东西】，给【谁】在【什么场景】用。
它接受【输入】，产出【输出】。
运行约束是【设备、网络、依赖、隐私等条件】。
本版不做【排除项】。
完成标准是：
1. 【操作 + 可观察结果】
2. 【操作 + 可观察结果】
3. 【操作 + 可观察结果】
先不要写代码。把仍不确定、且会影响实现的问题列出来问我。
```

需求确认后，把内容保存为项目根目录里的 `REQUIREMENT.md`，再进入 [定计划](/loop/plan/)。
