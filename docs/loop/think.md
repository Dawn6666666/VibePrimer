这一步的全部工作，是把「我想要」翻译成「什么算做好了」。

听起来像废话。但你打开任何一个初学者交给 Agent 的第一句话，基本都是"帮我做个 XX"——五个字，装着一个没被想清楚的项目。Agent 不会追问，它会猜。猜对了你走运，猜错了你花两小时删代码。

## 你要交出来的东西：一张需求卡

半页纸，六个格子。写完它大概 15 分钟，能省掉后面两小时的返工。

::: field-group

::: field 谁用
@type 具体的一个人
@required

不是"用户"，不是"学生群体"。是"我自己，在宿舍，用笔记本"，或者"我们班 40 个人，手机上打开看"。
:::

::: field 什么时候用
@type 场景 + 频率
@required

"每天晚上复盘今天学了什么"和"每学期开学填一次"，会导出完全不同的设计。
:::

::: field 输入是什么
@type 数据 / 操作
@required

用户要给你什么？一段文字、一个文件、一堆点击，还是什么都没有。
:::

::: field 输出是什么
@type 看得见的结果
@required

屏幕上出现什么、文件里留下什么、数据存到哪里。要具体到"长什么样"。
:::

::: field 约束
@type 硬条件
@required

运行在哪、能不能联网、有没有依赖、多久要交、你愿意花几小时。
:::

::: field 不做什么
@type 明确的排除项
@required

这一格最省时间。不写它，Agent 会免费送你一堆你没要的功能，而每个功能都是一个 bug 入口。
:::

:::

再加一栏：**验收标准**。它是需求卡的另一半，见下文。

## 一句「好需求」和一句「坏需求」

::: flex between gap="20"

<Card title="坏：形容词堆出来的需求" icon="carbon:close-outline">

> 帮我做一个好看的番茄钟，界面要现代，计时准确，最好有点动画。

问题不在"好看"，在于**没人知道什么时候算做完**。你验收的时候只能凭感觉，Agent 改到第五版你还在说"再现代一点"。

</Card>

<Card title="好：能被验证的需求" icon="carbon:checkmark-outline">

> 一个本地网页，双击打开就能用。中间一个大数字倒计时 25:00，下面两个按钮：开始/暂停、重置。点开始后数字每秒减 1；归零时页面标题变成「休息一下」，并响一声。刷新页面后回到 25:00。不要登录、不要后端、不要多语言。

每条都能当场试出来对错。这就是区别。

</Card>

:::

## 验收标准怎么写

一条验收标准必须满足三件事：**可观察**（看得见）、**可判定**（对或错）、**不依赖心情**。

| 写不出来的 | 改成 |
| --- | --- |
| 界面要好看 | 手机宽度 375px 时，两个按钮在同一行且不重叠；字号不小于 14px |
| 计时准确 | 点开始后数 600 秒，显示从 25:00 走到 15:00，误差不超过 1 秒 |
| 数据不能丢 | 关掉浏览器再打开，昨天记的三条还在 |
| 要有提示 | 输入为空时点提交，按钮下方出现红字「写点什么」 |
| 性能要好 | 课程表 30 条数据时，滚动不卡顿（体感），首屏 1 秒内出现 |

一条经验：**验收标准里不许出现形容词的比较级**。"更快""更简洁""更友好"都不合格，因为 Agent 无法知道你没说出口的基线在哪。

## 让 Agent 反过来问你

这是这一章最值钱的一个技巧。

你不需要一开始就想清楚所有事。你只需要**让 Agent 别急着写代码，先问你十个问题**。它问的十个问题，就是你的需求卡上还空着的格子。

::: chat title="Claude Code"

{.}

我要做一个番茄钟网页，本地双击就能用。先别写代码。用提问的方式帮我把需求问清楚：最多问我 10 个问题，一次问完，问那些会改变实现方式的问题，不要问配色。

{Claude}

好，10 个问题：

1. 25 分钟是固定的，还是允许用户改？如果允许改，改完要不要记住？
2. 一轮结束之后，是自动开始 5 分钟休息，还是等用户点？
3. "响一声"是用系统提示音，还是要一个音频文件？如果浏览器不允许自动播放声音，你接受"标题闪烁"代替吗？
4. 需要记录"今天完成了几个番茄"吗？如果需要，存哪里？
5. 关掉页面时正在计时，重新打开应该继续、暂停，还是归零？
6. 只在电脑上用，还是手机上也要能用？
7. 需要暂停后继续吗？还是只有"开始"和"重置"？
8. 时间显示用 `25:00` 还是 `24:59`？也就是 0 秒时显示 00:00 还是直接进休息？
9. 需要视觉进度（圆环/进度条），还是纯数字？
10. 你希望文件是一个 `index.html`，还是拆成 html/css/js 三个文件？

:::

十个问题，你回答完，需求卡就填满了。而且注意第 3、5 条——那是你自己想不到、但一定会踩的坑。

::: tip 为什么不让它直接写
因为它一旦开始写，它的每一个假设都会变成代码里的既成事实。你没有机会说"等等，我不是这个意思"。先用十分钟回答问题，比事后花一小时删代码便宜得多。
:::

## 「不做什么」清单

初学者最容易忽略的一格。它的作用不是限制你，是**挡住 Agent 的好意**。

以番茄钟为例，明确写下来：

- 不做登录、不做账号、不做云同步
- 不做多语言
- 不做主题切换（深色模式也不做）
- 不做任务清单，只做计时
- 不做数据导出
- 不用任何框架，不装任何依赖

最后一条尤其重要。你写"不用框架"，它就不会给你一个需要 `npm install` 才能跑的项目——这对"双击打开就能用"这条验收标准是决定性的。

## 卡住了怎么办

想不清楚的时候，别硬想，做三件事里的任意一件：

1. **找一个现成的东西，然后说它哪里不对。** "我要做一个像 Forest 那样的，但不要社交功能。" 比从零描述容易一百倍。
2. **先写「不做什么」。** 排除法比定义法简单。
3. **写下最笨的版本。** "如果只能有一个按钮，会是哪个按钮？" 从那里开始。

## 一句话模板

下次开口，把这句话填完再发出去：

```text
我要做一个【什么东西】，给【谁】在【什么场景】用。
它接受【输入】，产出【输出】。
它必须在【约束】下运行。
它不做【明确排除的东西】。
做完的标准是：
1. 【可观察的行为】
2. 【可观察的行为】
3. 【可观察的行为】
先不要写代码。把你不确定的地方列成问题问我，最多 10 个。
```

这段可以直接复制。它就是你后面四步的地基。
