需求确定后，不急于直接开始写代码。

如果没有步骤限制，Agent 容易一次性输出完整的 HTML、CSS 和 JavaScript 混合代码。一旦出现逻辑缺陷或样式错乱，排查和定位修改的成本会显著增加。

第二步是制定计划：让 Agent 把需求拆分成小任务，并在写业务代码前，先列出一份包含具体验收步骤的 `TODO.md`。

## 下达定计划指令

向 Agent 发送以下明确指令：

```text title="定计划提示词"
现在执行【定计划】：
先不要写 index.html！在根目录下生成 TODO.md，把实现拆成 3 个独立的小任务：
- 任务一：骨架搭建与静态样式（HTML 结构、居中排版、初始时间与按钮）
- 任务二：核心倒计时与状态流转（开始/暂停/继续/重置，归零停在 00:00 并修改网页标题）
- 任务三：持久化与完成计数（localStorage 存今日完成数与日期，跨天自动归零）
每项任务需标明：改动文件、核心逻辑、手动验收步骤。
```

::: tip 为什么提示词中要注明「先不要写代码」
如果不做限制，Agent 往往会直接生成全部代码。提前拆分任务能让每个步骤的改动保持在可控范围内，便于逐步审查与验证。
:::

## 真实的 TODO.md 清单

Agent 随后在项目根目录生成了 [TODO.md](file:///home/yoake/Code/pomodoro/TODO.md)（共 38 行），将宏观需求拆解为可独立交付、可独立验证的三个任务：

```markdown title="TODO.md"
# 实施计划：番茄钟 Demo

单一交付文件 `index.html`（内联 CSS + JS），按顺序完成三个任务，每个任务结束都能在浏览器里手动验证。

---

## 任务一：骨架搭建与静态样式

- **改动文件**：`index.html`（新建）
- **核心逻辑**：HTML 结构 + 内联 `<style>`。页面只含三块：大号时间文本（初始 `25:00`）、主按钮（初始文案 `开始`）、重置按钮。容器使用 flex 全屏居中，时间用等宽数字（`font-variant-numeric: tabular-nums`）避免逐秒抖动；不引入任何外部资源。
- **手动验收**：
  1. 双击 `index.html`，浏览器以 `file://` 打开，无控制台报错、无网络请求。
  2. 页面垂直水平居中，时间显示 `25:00`，按钮文案为 `开始`。
  3. 缩小窗口后布局不破版，不出现滚动条。

---

## 任务二：核心倒计时与状态流转

- **改动文件**：`index.html`（在任务一的基础上加内联 `<script>`）
- **核心逻辑**：维护 `idle / running / paused / finished` 四态与剩余秒数（初始 1500）。主按钮按状态切换行为与文案：`开始 → running`、`暂停 → paused`、`继续 → running`。用 `setInterval` 每秒扣减并渲染 `mm:ss`；归零时清除定时器、停在 `00:00`、进入 `finished`、把 `document.title` 改为「休息一下」。重置按钮任意时刻清定时器、回 1500、回 `idle`、连续点击不产生多个定时器。
- **手动验收**：
  1. 点开始后每秒 `-1` 递减，按钮变 `暂停`；点暂停数字停住、按钮变 `继续`；点继续接着走。
  2. 计时中点重置，立即回 `25:00` 且停止，按钮回 `开始`；连点重置不出负数、不加速。
  3. 把时长临时改为 3 秒验证：归零后停在 `00:00`，标题变为「休息一下」，主按钮不误导为可继续。

---

## 任务三：持久化与完成计数

- **改动文件**：`index.html`（增量修改任务二脚本，新增计数渲染节点与存储逻辑）
- **核心逻辑**：任务二归零分支里追加 `+1`。localStorage 存 `{ date: "YYYY-MM-DD", count: n }`（单 key）；读取时若 `date` 不等于今天则视为 0，写入时带上当天日期。计数文本渲染在页面上；读取失败 / JSON 损坏 / 隐私模式写不进时静默降级为内存计数，不抛错、不影响计时。计时进度不持久化，刷新必然回到 `25:00` 静止态。
- **手动验收**：
  1. 完成一次 3 秒倒计时后计数显示 `1`；再完成一次变 `2`。
  2. 刷新页面：时间回 `25:00`、按钮回 `开始`、标题正常，计数仍为 `2`。
  3. 手动把 localStorage 里的 `date` 改成昨天再刷新，计数归零，计时功能正常。
  4. DevTools 里写入非法 JSON 后刷新，页面不报错、计数从 0 开始。
```

## 审查计划时的三个关注点

拿到 Agent 列出的计划后，我们主要检查什么？

:::: card title="计划审查要点"
1. **职责单一**：每个步骤是否只改动必要的文件？例如第一步只写 HTML 与 CSS 样式，绝不引入 JavaScript 业务逻辑。
2. **可独立验证**：每一步完成后，是否有具体的手动测试方法？例如任务二提到的“把倒计时临时改成 3 秒快速验证归零”。
3. **异常与边界处理**：是否考虑了常见意外情况？例如数字跳动时的等宽防抖、连续点击按钮避免加速、存储数据异常时不报错。
::::

## 第二次提交：保存实施计划

确认计划合理后，让 Agent 将 `TODO.md` 提交到 Git：

::: steps
1. **向 Agent 发送提交指令**
   让 Agent 在终端中执行提交：

   ```text title="计划锁定提示词"
   计划很清晰。
   请在终端执行提交：把 TODO.md 提交，提交信息为 "docs: 建立三步实施计划"。
   ```

2. **Agent 调用终端执行提交**
   Agent 在终端中执行命令完成提交：

   ```bash title="终端执行输出"
   💻 [Bash]:
   $ cd /home/yoake/Code/pomodoro && git add TODO.md && git commit -m "docs: 建立三步实施计划"

   📋 [Result]:
   [main 74b2ef9] docs: 建立三步实施计划
    1 file changed, 38 insertions(+)
    create mode 100644 TODO.md
   ```
:::

此时仓库中已有需求文档和任务清单两次提交，目标和步骤明确后，点击下方「下一页」开始生成并运行任务一与任务二的代码。
