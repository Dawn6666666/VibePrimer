`REQUIREMENT.md` 已保存，现在让 Agent 读取它并给出计划。此阶段先不修改代码，方便你在生成前发现遗漏。

## 第一条提示词

```text
读取当前项目的 REQUIREMENT.md。
如果读不到，停止并告诉我，不要根据猜测补需求。
先不要写代码，也不要修改任何文件。

请输出：
1. 文件清单和每个文件的职责
2. 实现顺序，以及每一步的验证操作和预期结果
3. 最可能出问题的地方
4. 你准备排除的功能
5. 需求卡中每条验收标准分别由哪一步覆盖

约束：单个 index.html，无依赖、无框架、无构建步骤。
```

如果工具确实读不到文件，可以把需求卡全文粘贴到同一条消息里。不要只带一句“如果没有，我贴在下面”，下面却没有内容。

## 一份需要修改的计划

```text
文件清单
- index.html：页面结构
- style.css：样式
- script.js：逻辑
- README.md：说明

实施顺序
1. 三个文件骨架，显示 25:00 和两个按钮
2. 开始、暂停和重置
3. 归零处理
4. 今日完成数和 localStorage
5. 深色 / 浅色主题切换
6. README

风险
- setInterval 在后台标签页可能被节流
- 浏览器可能限制自动播放
```

这份计划有四个问题：拆文件违反单文件约束；主题切换不在需求里；风险项没有说明刷新和日期规则；验收标准没有逐项对应实施步骤。普通 CSS 和传统 JavaScript 拆文件后仍可双击运行，这里要求合并是因为本案例明确选择单文件交付，不要混淆两个原因。

## 修改后的 `TODO.md`

新建 `TODO.md`，保存下面的任务。它引用需求卡里的验收标准，不再复制一份不同版本。

```markdown
# 番茄钟任务清单

需求与验收标准见 REQUIREMENT.md。

- [ ] 1. 静态骨架：25:00、两个按钮、今日完成数
- [ ] 2. render()：把剩余秒数显示为 MM:SS，并同步页面标题
- [ ] 3. 开始、暂停、继续和重置：按钮文字与状态一致
- [ ] 4. 归零：停止计时、显示 00:00、修改标题，再次开始重新计时
- [ ] 5. 今日计数：自然归零加 1，保存日期和数量，处理无效数据
- [ ] 6. 边界检查：重复点击、后台标签页、刷新、跨天和 375px
- [ ] 7. README 与交付检查

每步完成后：查看 diff → 按对应验收标准操作 → 提交。
测试短时长后恢复 TOTAL = 25 * 60。
```

第 2、3 步联系很紧，实际执行时可以在计划里注明合并为一次小迭代。合并前要确认验收方法仍然清楚，不能借合并之名一次完成整个项目。

## 审查计划时保留什么

文件少不等于计划好，任务多也不等于考虑周全。你要检查每个文件是否必要、每步是否有可观察结果，以及计划是否覆盖了所有需求。需求之外的功能先移出本版，确有需要再另开任务。

:::: tip Plan Mode 和普通提示词
Claude Code 的 Plan Mode 可以提供额外的文件修改限制。其他工具也可以使用“先不要写代码”，但仍要查看实际 diff 和权限状态，自然语言指令不等于强制沙箱。
::::

需求和 TODO 都保存在项目里，新会话可以直接读取。现在开始第 1 条：

```text
按 TODO.md 做第 1 条。只完成静态骨架，做完停下来告诉我怎样验证。
```
