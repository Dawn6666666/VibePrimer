需求卡写完了，现在把它交给 Agent。

注意顺序：**不是"开始写"，是"先给方案"。**

## 第一条提示词

完整地贴进去，不要精简：

```text
读一下 REQUIREMENT.md（如果没有，我贴在下面）。
先不要写代码，也不要修改任何文件。

需求：一个本地番茄钟网页，25 分钟倒计时，开始/暂停、重置两个按钮，
显示今日完成数。单文件 index.html，双击就能打开，不装依赖，不联网。

给我四样东西：
1. 需要哪些文件，每个文件一句话说清职责
2. 实现顺序，每一步做完我该怎么验证
3. 你觉得最可能出问题的地方
4. 你会主动排除掉什么（也就是你决定不做的）

约束（重申）：单文件、无依赖、无框架、无构建步骤。
```

第 4 条是新增的。它逼 Agent 把"打算删掉什么"说出来——你会惊讶于它本来准备加多少东西。

## 它返回的计划

真实的输出大概长这样：

```text
文件清单（4 个）
- index.html   页面结构
- style.css    样式
- script.js    逻辑
- README.md    说明

实现顺序
1. 三个文件骨架，写死 25:00，两个按钮不可用 → 验证：打开能看到界面
2. 开始/暂停/重置逻辑 → 验证：数 5 秒，数字在动
3. 归零处理 → 验证：临时改成 5 秒
4. 今日完成数 + localStorage → 验证：刷新后还在
5. 深色/浅色主题切换 → 验证：点按钮能切
6. README

风险点
- setInterval 在后台标签页会被节流
- 自动播放限制

主动排除
- 不做自定义时长，不做休息倒计时，不做声音
```

看起来挺靠谱。**但它有四个问题，每一个都要你来发现。**

## 审一遍：我砍了什么

| 它写的 | 问题 | 我的处理 |
| --- | --- | --- |
| 拆成 `style.css` + `script.js` | 违反"单文件、双击就能打开" | 全部合进 `index.html` |
| 第 5 步做主题切换 | 需求卡里没有，属于"顺便" | 删掉，写进「以后再说」 |
| 风险点里没提状态 | 它只说定时器，没说刷新会丢什么 | 追问："刷新页面时，哪些东西该留、哪些该重置？" |
| 计划里没写 commit | 一个下午改崩了没得退 | 自己补：每完成一步提交一次 |

改完之后的计划：

```markdown
# TODO

- [ ] 1. 骨架：显示写死的 25:00 + 两个按钮（按钮先不响应）
- [ ] 2. render()：把剩余秒数变成 MM:SS
- [ ] 3. 开始/暂停：一个按钮切换，切换时更新按钮文字
- [ ] 4. 归零：到 0 停下，标题改「休息一下」
- [ ] 5. 重置：回到 25:00，清掉定时器
- [ ] 6. 今日完成数：归零时 +1，存 localStorage
- [ ] 7. README

每步做完：双击打开 → 试一次 → git commit
```

七条，每条都能在十分钟内验完。**这一步花了十二分钟，后面省了至少一小时。**

## 为什么"砍"比"加"重要

AI 的方案总是偏大：四个文件、六步、顺手带个主题切换。它不是想害你，它是按"一个完整的项目"来想的。

但你要的不是完整，是**今天能做完**。

一个可以背下来的判断：**在你的需求卡之外，它提到的每一个功能，都是新增的失败点。** 删掉它，你的项目就少一个坏掉的可能。

::: tip 如果你用 Claude Code
按 `Shift+Tab` 切到 Plan Mode，它会读文件、思考，但**不碰文件**。看完计划点同意才动手。

其他工具里没有专门的 Plan 模式也没关系——"先不要写代码，给我计划"这句话在任何地方都管用，效果一样。真正起作用的是这句话，不是那个按钮。
:::

## 一个细节：把需求写进文件

把需求卡贴进对话是一回事，存成 `REQUIREMENT.md` 是另一回事。

前者会随上下文被挤掉，后者一直在。而且它有个额外好处：**你可以直接说"对照 REQUIREMENT.md 检查一遍"**，这时它检查的是磁盘上的原文，不是你二十分钟前的记忆。

同理，TODO 也放文件里。做完一条打个勾，进度一目了然。

## 现在开始动手

计划有了，文件里也存着了。下一句：

```text
按 TODO 做第 1 条。只做第 1 条，做完停下来告诉我怎么验证。
```
