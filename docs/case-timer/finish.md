## 功能验收

<Gate group="timer" />

后台标签页的节流因环境而异，不要要求每个人都复现相同的落后秒数。验收时比较真实经过时间和剩余时间的变化；如果未出现节流，也可以对照错误版与修复版的计算方式。

## 补充边界测试

| 操作 | 预期结果 |
| --- | --- |
| 运行中重置，再开始 | 回到 25:00，重新计时不加速 |
| 暂停后重置，再开始 | 从 25:00 开始，按钮状态正确 |
| 连续点击重置 | 不报错、不出现负数、不增加今日数 |
| 归零后再次开始 | 从完整时长开始，不重复计算上一次完成 |
| 禁用或模拟不可用存储 | 计时仍可用，README 说明计数无法持久保存 |
| 浏览器缩放 150%，视口设为 375px | 数字和按钮不重叠，无意外横向滚动 |
| 关闭页面再打开 | 今日数保留，倒计时按需求回到 25:00 |

最后一条是本项目明确选择的行为，不是进度丢失。README 要写出来，避免使用者误以为支持关闭后续时。

## README 示例

```markdown
# 番茄钟

一个本地单页番茄钟，无外部依赖，页面不请求外部 API。

## 运行
双击 index.html。推荐使用已测试过的 Chrome 或 Edge。

## 使用
1. 点击「开始」启动 25 分钟倒计时。
2. 点击「暂停」暂停，再点「继续」接着计时。
3. 点击「重置」回到 25:00，不计入完成数。
4. 自然归零后显示 00:00 和「休息一下」，今日完成数加 1。
5. 归零后再次点击「开始」，进入下一轮完整计时。

## 数据与限制
- 今日完成数按本地日期保存在当前浏览器，重新打开后保留。
- 刷新或关闭页面不保存计时进度，重新打开回到 25:00。
- 存储不可用或网站数据被清除时，完成数无法持久保存。
- 不支持自定义时长、休息倒计时和声音提醒。

## 实现与验证
- 单个 index.html，使用原生 HTML / CSS / JavaScript。
- 使用 Date.now() 与目标结束时间计算剩余时间。
- 已按 REQUIREMENT.md 测试八条功能标准，并检查重复点击和窄屏布局。

## AI 使用说明
按实际情况说明 AI 与本人分别完成了哪些工作。
```

“已知限制”写真实行为和未覆盖范围即可。没有发现问题时，可以写“在当前测试范围内暂未发现其他问题”，不要为了让这一节显得充实而编造 bug。

## 清理与提交

删除临时调试日志和注释掉的废代码，保留解释非显而易见原因的注释。`TODO.md` 可以保留为过程记录，也可以在确认 `REQUIREMENT.md` 和 README 已包含必要信息后移除，不必机械删除。

清理后重新打开页面，至少再测开始、暂停、继续、重置、归零和刷新，然后提交：

```bash
git add .
git commit -m "完成番茄钟交付版"
```

## 选择交付方式

| 方式 | 操作 |
| --- | --- |
| 压缩包 | 打包项目文件，通常不包含 `.git` 和 `node_modules` |
| GitHub 仓库 | 首次配置远程地址并推送，README 会显示在仓库首页 |
| GitHub Pages | 在 Pages 中选择 Deploy from a branch、`main` 和 `/ (root)`，保存后打开部署地址复测 |

首次推送和 Pages 的完整步骤见 [检查并交付](/loop/ship/)。本地版不请求外部 API；一旦部署，文件就会上传到托管平台，README 不要写成任何使用方式都“不上传数据”。
