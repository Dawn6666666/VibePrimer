最后一个小时，做三件事：验收、写说明、打包。

## 一、对着需求卡验收

你的 `REQUIREMENT.md` 还在项目里。逐条过：

<Gate group="timer" />

第七条（后台标签页）很多人跳过，因为"太麻烦"。麻烦也试一次——你会发现 30 秒的差值肉眼可见。

## 二、边界测试

界面的东西，光靠逻辑测试不够。手动点：

| 试什么 | 期望 |
| --- | --- |
| 连点「开始」十次 | 速度不变，按钮文字正确 |
| 连点「重置」十次 | 回到 25:00，不报错，不变负数 |
| 开始 → 重置 → 开始 | 正常走，不出现两个计时器 |
| 窗口缩到手机宽度（375px） | 数字不换行、按钮不重叠 |
| 浏览器缩放 150% | 布局不散 |
| 关掉网页再打开 | 今日数还在，倒计时回到 25:00 |

最后一条注意：**倒计时回到 25:00 是设计，不是 bug。** 你的需求卡里没要求记住进度，所以这是对的。写清楚这点很重要——不然别人会以为它坏了。

## 三、README

二十分钟，五节。别写多。

```markdown
# 番茄钟

一个本地单页番茄钟。双击 `index.html` 就能用，不需要安装任何东西，不联网。

## 怎么用
1. 点「开始」开始 25 分钟倒计时，按钮变成「暂停」
2. 再点暂停，点「继续」接着走
3. 点「重置」回到 25:00
4. 倒计时归零时，页面标题变成「休息一下」，「今日完成」+1

## 特性
- 单文件，零依赖，离线可用
- 用时间戳计算剩余时间，切到后台标签页也不会变慢
- 今日完成数存在浏览器本地，刷新不丢，跨天自动清零

## 已知问题
- 不支持自定义时长（25 分钟写死）
- 没有休息倒计时
- 没有声音提醒（浏览器会拦截自动播放）
- 只在 Chrome / Edge 上测过

## 实现说明
- 原生 HTML / CSS / JavaScript，无框架
- 状态：`remain`（剩余秒数）、`endAt`（结束时间戳）、`running`（是否在跑）
- 计时用 `Date.now()` 差值，不用累加计数
- 由 Claude Code 辅助生成；需求、验收标准、bug 定位与验收由本人完成
```

「已知问题」那一节不要省。它传递的信息是：**我知道它哪里不完美**。这比"完美无缺"可信一百倍，而且省掉别人来问你。

## 四、清场

两分钟，但必须做：

1. 搜一遍 `console.log`，全删
2. 删掉注释掉的旧代码（有 Git，不用怕丢）
3. 删掉 `TODO.md` 里已经完成的条目，或者整个删掉——它是过程文件，不是交付物
4. 最后提交一次，message 写「交付版」

```bash
git add .
git commit -m "交付版"
```

## 五、交出去

| 方式 | 怎么做 | 适合 |
| --- | --- | --- |
| 压缩包 | 整个文件夹打包，**不要**包含 `.git` 和 `node_modules` | 交作业 |
| GitHub | 推到仓库，README 就是首页 | 想留个记录 |
| GitHub Pages | Settings → Pages → 选分支 | 想要个链接 |

如果你要演示，截三张图：初始状态、计时中、归零提示。截图前把书签栏收起来。

## 复盘：这一圈你做了什么

| 步骤 | 你实际做的事 | 时间 |
| --- | --- | --- |
| 想清楚 | 回答了 10 个问题，写了需求卡和 6 条验收标准 | 20 分钟 |
| 定计划 | 拿到 4 文件 + 6 步的计划，砍成 1 文件 + 7 步 | 12 分钟 |
| 生成并运行 | 两条任务，两次 diff，两次 commit | 35 分钟 |
| 发现问题并修改 | 4 个 bug，其中 1 个要你自己复现才看得见 | 45 分钟 |
| 检查并交付 | 验收、边界测试、README、打包 | 40 分钟 |

两个半小时。真正"生成代码"的时间，加起来不到五分钟。

**这就是 Vibe Coding 的真实比例。** 剩下的时间全在：想清楚、看明白、验证、修。

::: warning 如果你只记得一件事
记住比例。你以为的"AI 帮我写代码"，实际是"我在用 AI 做工程"。慢的那部分不是浪费，那部分就是你。
:::

## 你现在能回答的问题

走完这一圈，下面这些问题你应该答得上来。答不上来，回去补：

- 这个程序的状态存在哪几个变量里？
- 为什么用时间戳算剩余，而不是每秒减一？
- 点两次「开始」会发生什么？为什么？
- `localStorage` 存数字有什么坑？
- 如果要把时长改成可配置的，你要动哪几个地方？

最后一个问题最重要。**能回答它，说明这个项目是你的。**
