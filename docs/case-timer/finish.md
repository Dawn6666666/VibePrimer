## 全量功能验收清单

对照最初在 `REQUIREMENT.md` 中立下的 8 项验收标准，逐一核验：

| # | 验收场景 | 操作方式 | 预期表现 | 实测状态 |
| --- | --- | --- | --- | --- |
| 1 | **双击即用** | 浏览器直接以 `file://` 打开 `index.html` | 首屏居中显示 `25:00`，控制台 0 报错、0 网络请求 | ✅ 通过 |
| 2 | **正常倒计时** | 点「开始」按钮 | 秒数平稳递减，主按钮即时变为「暂停」 | ✅ 通过 |
| 3 | **暂停与继续** | 点「暂停」后等几秒再点「继续」 | 暂停时数字完全停住，继续后无缝衔接原时间 | ✅ 通过 |
| 4 | **重置防加速** | 运行中点「重置」，再反复快速连点「重置」 | 立刻恢复 `25:00`，不加速、不跑出负数、不计数 | ✅ 通过 |
| 5 | **归零与标题** | 临时将时长调为 3 秒跑完一轮 | 停在 `00:00`，网页标题变为「休息一下」，主按钮置灰禁用 | ✅ 通过 |
| 6 | **计数与持久化** | 归零后观察页面计数与刷新表现 | 页面显示「今日完成：1 次」，刷新页面后计数依然为 1 | ✅ 通过 |
| 7 | **跨天自动归零** | 手动修改存储日期为昨天 | 刷新页面后计数自动归零，不产生任何异常报错 | ✅ 通过 |
| 8 | **破坏性容错** | 手动在存储中灌入损坏 JSON 字符串 | 页面优雅降级显示 0 次，控制台 0 报错 | ✅ 通过 |

## 过程清理与 .gitignore 配置

开发过程中产生的截图（如 `imgs/`）、临时测试文件，不应作为正式代码散落在工作区。

按照以下步骤让 Agent 创建 `.gitignore` 进行隔离与收尾提交：

::: steps
1. **向 Agent 发送收尾指令**
   命令 Agent 创建配置并完成最后一次资产隔离打卡：

   ```text title="收尾提示词"
   全功能验收通过！跨天检测与容错降级逻辑非常完备。
   请执行最后的收尾工作：
   1. 在根目录下生成 .gitignore，忽略 imgs/ 目录，提交信息为 "chore: 忽略本地截图目录"。
   2. 终端打印输出完整的 git log --oneline 提交历史，宣布项目正式完工！
   ```

2. **Agent 自动执行隔离并入库**
   Agent 写入忽略规则并完成最后一次 Git 交付打卡：

   ```bash title="收尾提交日志"
   💻 [Bash]:
   $ echo "imgs/" > .gitignore && git add .gitignore && git commit -m "chore: 忽略本地截图目录"

   📋 [Result]:
   [main dd0478a] chore: 忽略本地截图目录
    1 file changed, 1 insertion(+)
    create mode 100644 .gitignore
   ```
:::

运行 `git log --oneline`，检视整个演练过程产生的提交线：

这是一份教科书般的提交历史：
- **无废话、无混杂**：每一个 commit 都对应五步循环中的一个具体里程碑。
- **无回滚、无返工**：因为每一步都在计划内单任务推进，做完立即审查 diff，错误在萌芽状态就被掐灭。
- **天然可追溯**：任何时刻需要回溯，只需 `git checkout <commit>` 就能回到对应的阶段。

## 五步循环实战复盘

回顾这次实战，真正支撑我们从零到交付的核心不是高深的算法，而是严谨的结对纪律：

:::: card title="五步循环核心复盘"
1. **想清楚**：用 10 个问题框住 Agent 的发散性，先立合同（`REQUIREMENT.md`），先打根提交。
2. **定计划**：不给大任务，强行切分为可独立验收的小块（`TODO.md`），不准提前写代码。
3. **生成并运行**：严格单任务派发，先骨架后逻辑，做完立即运行直测。
4. **盯差量与修边界**：代码进库前必看 `git diff`，主动考虑时区偏差、存储熔断和异常刷新。
5. **检查并交付**：对照验收清单逐条核对，清理工作区，固化提交树。
::::
