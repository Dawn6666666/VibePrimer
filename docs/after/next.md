两个案例走完，你现在会做的：**一个能跑、能改、能交的网页小工具。**

接下来只有三条路，按难度排。

## 路一 · 给自己做工具（推荐）

最快见效，也最容易坚持。因为**你不用讨好任何人，包括老师**。

做法只有一步：列一张「我每天都在忍的十件事」清单。

比如我自己会写：

```md
1. 每周的课表要截图存在相册里，翻起来慢
2. 记账记了三天就放弃，因为每次都要手动分类
3. 学期末要交的读书笔记，格式每次都不一样
4. 宿舍的洗衣机和烘干机哪个空着，得下楼看
5. 想看的东西堆在小红书收藏里，从来不打开
```

然后挑一条标准：**三小时内能做完的**。做完之后再挑下一条。

一次做三个，一个也做不成。

| 你能做 | 需要多久 | 用到的技术 |
|---|---|---|
| 课表 / 倒计时 / 番茄钟 | 3 小时 | 数据 + 渲染 |
| 记账 / 打卡 / 学习记录 | 一个周末 | 表单 + localStorage + 筛选 |
| 单词卡 / 复习提醒 | 一个周末 | 数组 + 随机 + 日期 |
| 宿舍公共物品借用表 | 两天 | 表单 + 列表 + 时间 |

全都用原生 JS 就能做。**不需要框架。**

## 路二 · 接手别人的项目

这一步比路一难，但它教你一件路一教不了的事：**读别人的代码**。

找法：GitHub 上搜你熟悉的语言 + `good first issue`，专挑三百行以内、有 `README` 的项目。

第一次别想加功能。做这三件事之一就够了：

- 把 README 里一句让人看不懂的话改清楚
- 补一个输入校验（用户输入空的时候报错）
- 把一个写死的数字改成常量

做完提一个 PR，等回复。**被拒绝是常态**，而且拒绝的理由通常比代码本身更有价值。

::: warning 别一上手就找大项目
给 Vue、React 这类框架提 PR，你会在读构建脚本的两小时里放弃。

先找一个人的小项目，有 issue，最近三个月还在更新。
:::

## 路三 · 找两三个人做一个有人用的东西

校园里的小痛点，两三个人，一个学期。

关键是「有人用」——**这不是要你创业，是让项目有反馈来源**。

| 想法 | 为什么有反馈 |
|---|---|
| 社团活动的报名页 | 报名的人会抱怨表单难填 |
| 课程资料共享页 | 同学会说"找不到去年的"
| 考试倒计时页面 | 有人会问"能不能加自习室列表" |
| 宿舍楼的物品借用表 | 借东西的人会自己加条目 |

有了真实用户，你会第一次遇到：**用户不按你想的用**。这件事比技术难，也比技术值钱。

## 两周怎么安排

如果你从今天开始：

| 时间 | 做什么 | 花多久 |
|---|---|---|
| 第 1–2 天 | 列十件事，挑一件 | 30 分钟 |
| 第 3 天 | 需求访谈 + 需求卡 + 验收标准 | 1 小时 |
| 第 4 天 | 要方案，砍到 5 步 | 40 分钟 |
| 第 5–8 天 | 分步做，每天一次提交 | 每天 1 小时 |
| 第 9–10 天 | 找三个 bug（真的找，别等着它出错） | 2 小时 |
| 第 11 天 | 边界测试 + README | 1 小时 |
| 第 12 天 | 交给一个真实用户，看他用 | 20 分钟 |
| 第 13–14 天 | 按他的反馈改一处，收尾 | 1 小时 |

第 12 天那 20 分钟最重要。**你会在旁边看他点错按钮，然后一句话都不敢说。**

## 别一上手就做这四类

| 类型 | 为什么不 |
|---|---|
| 聊天机器人 | 你真正在做的是"接一个 API"，学到的东西比做课程表少 |
| 待办清单 / 博客 | 教程里有二十个亿版本，你没有真实的痛点要解决 |
| 电商 / 后台管理系统 copy | 需要假数据、假用户、假权限，你没那时间 |
| 什么都要有的 App | 三小时的项目长成了三周的项目，然后你放弃 |

这四类**不是不该做**，是不该当作**第一个做了能交的东西**。它们适合当练习里的第二步。

## 什么时候该学框架

三个信号，出现两个就可以考虑：

1. 你第三次手写同样的「把数据渲染成列表」
2. 你需要在多个页面之间共享状态，而且开始出错
3. 你的 `app.js` 超过 800 行，改一个功能要牵动五处

在这之前，框架只会让你多背一套规则，不会让你多做出一个功能。

::: tip 一个更准的信号
当你开始**厌倦**手写某件事，而且厌倦的原因是"这活儿重复"而不是"我不会"——那才是该用工具的时机。
:::

## 最后

你现在会的东西，超过大部分"学过编程"的人——不是因为你写的代码多，是因为你知道**一个东西怎么从想法变成能交付的成品**。

这条路剩下的部分，都是重复和耐心：

- 再做十个自己的小工具
- 读两百个人的代码
- 交五个被人挑毛病的 PR

工具会一直换。今天你在用的 Agent，明年可能改名、涨价、或者消失。

**工作流不会。** 上面这五个步骤，从六十年前的程序员到现在，没怎么变过。
