下面按项目推进顺序列出二十个常见问题。表格用于快速定位，详细操作请进入对应章节。

## 开工前

| 坑 | 常见症状 | 为什么 | 怎么处理 |
| --- | --- | --- | --- |
| 1. 路径过于复杂 | 某些旧脚本报 ENOENT 或找不到文件 | 并非所有工具都能正确处理中文、空格和特殊字符 | 初学项目优先用 `C:\dev\xxx` 或 `~/dev/xxx`；同时读取真实报错，不只怪路径 |
| 2. 只打开单个文件 | Agent 找不到项目说明和旁边文件 | 当前工作区缺少项目上下文 | 用「打开文件夹」打开项目根目录 |
| 3. Agent 工作目录不对 | 文件建到别处，或只能聊天 | CLI 从错误目录启动，或使用了纯 Chat 模式 | 检查 `pwd`、打开的项目和 Agent 模式 |
| 4. 没有 Git 检查点 | 改坏后只能手动撤销 | 没有提交就无法按历史恢复 | 先写 `.gitignore`，检查密钥和隐私，再首次提交；后续继续提交小版本 |
| 5. API 用量失控 | 长任务产生意外费用 | 订阅不一定覆盖 API，也不一定形成硬上限 | 设置服务商支持的预算和额度，关闭不需要的自动充值，限制循环并查看用量 |

## 提需求时

| 坑 | 常见症状 | 为什么 | 怎么处理 |
| --- | --- | --- | --- |
| 6. 一句话直接开工 | 成品采用了很多你没选的默认行为 | 输入缺少关键决定 | 先访谈并写 `REQUIREMENT.md` |
| 7. 全是形容词 | “现代一点”改了很多版仍不满意 | 没有可判定标准 | 改成尺寸、操作和可观察结果 |
| 8. 没有验收标准 | 不知道什么时候算完成 | 需求和完成条件没有对应 | 为主要行为写操作与预期结果 |
| 9. 一次要太多 | 几百行代码直接接受，后续无法定位 | 审查和测试范围过大 | 按可独立验收的任务生成；行数只作提醒 |
| 10. 不说排除项 | 多出登录、主题和依赖 | Agent 按常见产品形态补全 | 写明本版不做的功能和修改范围 |
| 11. 需求变了但文件没改 | Agent 按旧需求写，你按新需求验收 | 存在两套约定 | 先更新需求、TODO 和验收，再继续 |
| 12. 只问通用教程 | 回答很长，却接不上当前项目 | 缺少项目上下文 | 给出相关文件，问当前项目里的具体用法 |

## 写代码时

| 坑 | 常见症状 | 为什么 | 怎么处理 |
| --- | --- | --- | --- |
| 13. 不看代码改动 | 无关函数或配置被修改 | 接受了未审查的实际改动 | 查看文件、行为、依赖和测试，不只看行数 |
| 14. 状态转换不一致 | 按钮显示暂停，实际有多个计时器 | 多处代码分别修改相关状态，没有统一转换 | 明确权威状态，集中开始、暂停和重置逻辑；`remain` 与 `endAt` 可以共存，但要保持同步 |
| 15. 只信“已修复” | 声明完成，实际未运行或仍失败 | 文字结论不能替代工具记录和复测 | 查看实际命令与输出，自己独立复跑 |
| 16. 报错信息太少 | Agent 连续猜改多个位置 | 缺少复现和证据 | 提供操作、期望、实际、频率和报错原文 |

## 收尾时

| 坑 | 常见症状 | 为什么 | 怎么处理 |
| --- | --- | --- | --- |
| 17. 只测正常路径 | 重复点击、空输入或刷新后出错 | 边界没有进入验收 | 按项目风险测试重复、空值、超长、刷新和存储失败 |
| 18. 密钥进入仓库或前端 | 推送后收到泄露提醒，或浏览器可读取 key | Git 历史会保留，纯前端也无法藏密钥 | 立即吊销轮换；Node 正确加载环境变量，保密 key 放后端 |
| 19. README 不足 | 换台电脑不会启动 | 运行条件和步骤只在作者脑中 | 写运行、使用、已知限制、验证和 AI 使用说明 |
| 20. 部署后资源 404 | 本地正常，线上白屏 | base 路径、大小写、构建输出或路由配置不一致 | 看 Network 和 Console 的实际 URL；静态文件查相对路径，构建工具查 `base`，再打开线上链接复测 |

## 按当前任务回查

环境问题时看 1–5，需求反复时看 6–12，代码修改失控时看 13–16，交付失败时看 17–20。读完一章只能让你见过对应解法，不能保证以后不再遇到。

密钥、恶意依赖和隐私泄露可能造成实际损失，不能把它们当成“只费时间”的环境问题。其余问题也应根据影响范围处理，不要机械套同一条规则。
