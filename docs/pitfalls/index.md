这些不是"可能会遇到的问题"，是**我见过的、你自己也会踩的**。

按你踩到的顺序排。每一条三行：什么症状、为什么、怎么办。

## 一 · 开工前的坑（5 个）

| 坑 | 症状 | 怎么办 |
|---|---|---|
| 1. 文件夹路径带中文或空格 | `code .` 报错，`npm` 找不到文件，各种奇怪的 ENOENT | 项目一律放 `C:\dev\xxx` 或 `~/dev/xxx`。中文和空格是玄学错误的头号来源 |
| 2. 打开的是文件不是文件夹 | Agent 说"我没看到你的项目"，改的文件在别处 | 永远「打开文件夹」，左边那一栏要能看到完整文件树 |
| 3. 装了 Agent 但没装到项目里 | 它只能聊天，不能读文件 | 在项目文件夹里启动它。Claude Code 是 `cd` 进去再敲 `claude`，不是随便哪都能用 |
| 4. 没 `git init` 就开始改 | 改坏了没得退，只能手动删 | 建文件夹第一件事：`git init` + 第一次提交 |
| 5. 用裸 API key 跑长任务 | 半夜跑掉几十块 | 用有额度上限的订阅版。要测 API 就用几毛钱的模型 |

第 1 条值得多说一句：**中文路径不是绝对的错**，但它会让你在搜索报错时，搜到的全是别人在 Windows 上的其他问题。你付不起那个时间。

## 二 · 提需求时的坑（7 个）

| 坑 | 症状 | 怎么办 |
|---|---|---|
| 6. 一句话开工 | "帮我做个 XX"，它给你一个别人的 XX | 先访谈：让它问你 10 个问题（[想清楚](/loop/think/)） |
| 7. 需求里全是形容词 | "要好看""要流畅""现代一点" | 换成可数的：一屏放几门课、点击后 0.2 秒内有反应 |
| 8. 没有验收标准 | 做完不知道算不算完，改到什么时候都像没改完 | 写 6–8 条能打勾的（[案例一](/case-timer/requirement/)） |
| 9. 一次要太多 | 它给了 800 行，你一行没读就点了接受 | 一轮只做一件能看见的事。diff 超过 200 行就该拆 |
| 10. 只描述想要什么，不说不要什么 | 它顺手加了登录、加了深色模式、加了三个依赖 | 每条提示词末尾加一句「不要做 X」 |
| 11. 中途改需求但不告诉它 | 它按旧需求写，你按新需求验收，永远对不上 | 改需求就停下来改 REQUIREMENT.md，再让它继续 |
| 12. 把 AI 当搜索引擎 | 问"React 怎么用"，得到一段你读不懂的教程 | 要它给**你这个项目里**的用法，不要通用教程 |

第 10 条是最高性价比的一句。「不要引入任何依赖」「不要改 HTML 结构」「不要动 `.env`」——每加一句，就少一次返工。

## 三 · 写代码时的坑（4 个）

| 坑 | 症状 | 怎么办 |
|---|---|---|
| 13. 不看 diff 就接受 | 它顺手删了一个你没注意的函数，三天后才发现 | 每次接受前看三样：改了哪些文件、新增多少行、有没有新依赖 |
| 14. 一个状态两个源头 | 计时器同时靠 `remain` 和 `endAt` 算，越跑越偏 | 一个数据只有一个权威来源，其他地方都是它的投影（[案例一 Bug 2](/case-timer/bug/)） |
| 15. 相信它说的"已修复" | 它说修好了，其实什么都没改，或者改错了地方 | 要证据：让它把改动贴出来，或者你自己跑一遍验收 |
| 16. 报错只贴一句"不行" | 它开始瞎猜，一次改五个地方 | 四句话报告：做了什么、期待什么、实际什么、报错原文（[发现问题并修改](/loop/fix/)） |

第 15 条不是它撒谎，是**它真的认为改好了**。模型对自己的输出没有"跑过一遍"的体验，它只是觉得这段代码看起来对。所以"已修复"这三个字，在你亲手跑过之前等于零。

## 四 · 收尾时的坑（4 个）

| 坑 | 症状 | 怎么办 |
|---|---|---|
| 17. 只测了正常路径 | 演示时点了两下按钮就白屏 | 连点五次、空输入、超长输入、刷新、换浏览器 |
| 18. 把 key 写进代码 | 推到 GitHub，几分钟后收到密钥泄露提醒 | key 一律进 `.env`，`.env` 一律进 `.gitignore` |
| 19. 没有 README | 三天后你自己都不知道怎么跑 | 五节：怎么用、特性、已知问题、实现说明、AI 声明 |
| 20. 部署后路径错 | 本地好好的，线上白屏，控制台一堆 404 | 用相对路径；部署后一定要打开线上链接看一次 |

第 18 条补充一个数字：有研究统计过，AI 辅助提交的代码里泄露密钥的比例，大约是人工提交的两倍。原因很简单——**它不知道哪个字符串是真的 key**，它只知道这里"看起来该填一个 key"。

剩下几条不是知识问题，是**习惯问题**：每次接受前看 diff、每次部署后打开链接、每次写提示词加一句"不要做"。

习惯没法读一遍就装好。所以这些坑，你还是会踩几个。踩到的时候回来看一眼，比现在背下来有用。

::: tip 如果只记一条
**看不懂的代码不进你的项目。**

这一条能挡掉上面一半的坑——不看 diff 会进来你看不懂的代码，接受"已修复"会进来你看不懂的代码，一次要太多会进来你看不懂的代码。

挡不住的那一半，是环境问题。环境问题不致命，只费时间。
:::
