向 AI 描述需求时，最容易出现沟通偏差的往往是不知道要做的东西在技术上叫什么。用模糊的日常大白话描述，容易让 Agent 误判组件类型并写出臃肿的代码。

## 推荐查阅：VibeHub 术语图鉴

[VibeHub](https://vibe-hub.org/) 是一个专门把日常大白话翻译成准确技术术语的可视化图鉴，收录了前端 UI 组件、后端架构、产品交互、测试、Git 与 AI 等 360 多个条目。

每个条目都配有日常场景问法、真实运行效果与参数边界，例如：
- 把“选省市区的联动下拉框”翻译为 **级联选择器 Cascader**
- 把“从屏幕边缘滑出的侧边浮层”翻译为 **抽屉 Drawer**
- 把“点提交后右上角短暂浮现并自动消失的提示”翻译为 **轻提示 Toast**
- 把“内容还没加载出来时灰色的条状占位”翻译为 **骨架屏 Skeleton**
- 把“可以左右拖着轮播的卡片群”翻译为 **走马灯 Carousel**

遇到具体界面控件、动画交互或后端概念不知道怎样跟 AI 表达时，建议直接访问 [VibeHub 官网](https://vibe-hub.org/) 检索预览。

## 本教程高频术语

以下整理了本教程实战与工程实践中反复出现的核心概念：

### 模型与协作

| 术语 | 说明 |
| :--- | :--- |
| **Agent** | 具备工具调用能力、能读取文件、修改代码或运行终端指令的 AI 系统。 |
| **上下文** | 模型在单次生成回答时能直接利用的信息窗口，包含历史对话、注入的文件与工具执行返回。 |
| **上下文污染** | 会话轮次过多或文件过大导致有效注意力分散，模型遵从指令的能力随之下降。适时清理对话是重要习惯。 |
| **模型幻觉** | 模型生成看似合理、实际并不存在或错误的内容（如编造不存在的 npm 依赖包名或虚构 API 参数）。 |
| **提示词** | 发给模型的任务说明材料。工程任务中一般包含角色、任务、上下文、约束与验收标准。 |
| **系统提示词** | 由平台或调用方预置的高优先级全局指令，通常用于约束模型的输出格式和安全边界。 |
| **Token** | 大语言模型处理文本的基本计量单位，单词或汉字会被切分为对应的 token 碎片进行计算。 |

### Git 与项目

| 术语 | 说明 |
| :--- | :--- |
| **Git 仓库** | 由 Git 进行版本追踪的项目目录。执行 `git init` 即可在当前目录创建本地仓库。 |
| **Git 提交** | 代码库在某一历史节点的状态快照。新增或修改的文件需先执行暂存操作才能纳入提交。 |
| **Diff** | 两个版本或两次修改之间的差异对比。审查 Agent 改动时，重点看行为逻辑与文件范围，不只看修改行数。 |
| **项目依赖** | 项目运行或构建所需的外部第三方代码库。引入前需确认其必要性、维护状态与安全性。 |
| **构建** | 将源代码通过编译、打包等手段转换为适合生产部署产物的过程。纯原生静态项目通常无需构建步骤。 |
| **静态站点** | 服务器直接返回 HTML、CSS、JS 等静态文件，不需要服务器在收到访问时动态运行计算脚本。 |
| **部署** | 将本地可运行的代码发布到托管服务器（如 GitHub Pages、Cloudflare Pages），让外部用户可公开访问。 |

### 前端与数据

| 术语 | 说明 |
| :--- | :--- |
| **DOM** | 浏览器将 HTML 文本解析生成的对象节点树，JavaScript 脚本可通过操作 DOM 动态更新页面内容。 |
| **页面状态** | 驱动界面展示与业务逻辑的核心变量集合（如倒计时剩余秒数、当前选中的周次、运行开关等）。 |
| **事件监听** | 针对点击、键盘输入、页面加载等用户或系统行为设置的响应函数，触发时执行对应的业务逻辑。 |
| **localStorage** | 浏览器提供的本地字符串键值存储方案。同源策略、无痕模式以及清除浏览器缓存均会影响其读写。 |
| **JSON** | 跨语言通用的轻量级文本数据交换格式。向本地存储写入时需序列化，读取解析时需防范格式损坏异常。 |
| **rowspan** | 表格单元格纵向合并的行数属性。被跨行合并覆盖的后续行位置不能重复输出单元格。 |
| **API Key** | 调用外部商业模型或云服务时使用的身份凭据。私有密钥绝不能直接暴露在纯前端公开代码中。 |
| **XSS 漏洞** | 不受信任的外部输入被浏览器当成可执行脚本直接运行的安全隐患。纯文本渲染应使用 `textContent` 替代 `innerHTML`。 |

### 工程与测试

| 术语 | 说明 |
| :--- | :--- |
| **代码重构** | 在保持软件外部行为与输出完全一致的前提下，优化代码的内部架构与可读性。 |
| **边界条件** | 空输入、零、负数、极端长度、重复值、越界等容易被常规逻辑忽略的特殊情况。 |
| **功能回归** | 修复当前问题或新增代码时，意外破坏了先前已经正常工作的原有功能。充分的复测用于防范回归。 |
| **纯函数** | 相同的输入必定得到完全相同的输出，且执行过程中不修改任何外部状态的函数，极易编写单元测试。 |
| **断言** | 测试代码中对执行结果是否符合预期的硬性判断，如断言格式化函数返回的值等于目标字符串。 |
| **最小可行产品** | 包含核心链路、能验证实际需求与使用场景的最小完整版本，避免一开始陷入过度设计。 |
| **规格驱动开发** | 动手编码前先写明需求边界与完成标准，再根据规格清单拆解任务并逐一验收。 |
