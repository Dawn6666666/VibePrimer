## 提示与模型

| 术语 | 在这里指什么 |
| --- | --- |
| Agent（智能体） | 能通过工具读取文件、修改代码或运行命令的 AI 系统。具体能力取决于产品、配置和权限，网页产品也可能具备这些能力 |
| 上下文（Context） | 模型当前生成回答时可以利用的信息，包括对话、文件内容和工具输出；不等于长期记忆 |
| 上下文腐坏（Context rot） | 一些研究和实践中观察到的现象：输入变长后，模型利用其中信息的表现下降。程度因模型和任务而异 |
| 幻觉（Hallucination） | 生成了看似可信、实际错误或无依据的内容，例如不存在的包名。安装报 404 还需排查拼写、版本和 registry，不能仅凭 404 判定幻觉 |
| 提示词（Prompt） | 发给模型的指令和材料。编程任务里通常包含目标、上下文、约束和验收 |
| 系统提示词（System prompt） | 由产品或调用方设置的高优先级指令。API、本地产品等场景可能允许配置，普通聊天用户未必能修改 |
| token | 模型处理文本的单位，划分方式取决于分词器。额度和价格也可能按请求、时间或订阅配额计算，不都按 token |

## Git 与项目

| 术语 | 在这里指什么 |
| --- | --- |
| 仓库（Repository / repo） | 由 Git 记录历史的项目。`git init` 会在当前目录创建本地仓库 |
| 提交（Commit） | 一次被纳入提交的变更快照及说明。新文件要先暂存，不会仅因存在于文件夹就自动进入提交 |
| diff | 两个版本之间的差异。审查 Agent 改动时，重点看行为、文件和依赖，不只看增减行数 |
| 依赖（Dependency） | 项目需要的外部代码包或工具。安装前要核对名称、来源、用途和维护情况 |
| 构建（Build） | 把源码转换成可部署产物的步骤。两个案例直接运行源文件，不需要构建 |
| 静态站点（Static site） | 服务器直接提供 HTML、CSS、JavaScript 等文件，不要求服务器为每次访问动态生成页面 |
| 部署（Deploy） | 把可运行的项目发布到指定环境，例如 GitHub Pages。部署会把文件上传到托管平台，不等于仍然只在本地 |

## 前端与数据

| 术语 | 在这里指什么 |
| --- | --- |
| DOM | 浏览器表示页面结构的节点树，JavaScript 可以通过它读取和修改页面 |
| 事件（Event） | 点击、输入、加载完成等发生的事情。`onclick` 后面的函数是事件处理函数，不是事件本身 |
| 状态（State） | 会影响程序行为和界面的数据，例如 `remain`、`running`、`week` |
| 渲染（Render） | 根据数据更新界面。渲染可以有条件显示，但复杂业务计算和数据修改宜放在其他函数 |
| localStorage | 浏览器提供的字符串键值存储。同源、隐私模式、`file://` 行为和清除网站数据都会影响可用性 |
| JSON | 一种文本数据格式。对象写入 localStorage 前常用 `JSON.stringify`，读取后用 `JSON.parse`，还要处理损坏数据 |
| rowspan | 表格单元格纵向跨越的行数。被跨行占用的后续位置不能再输出一个 `<td>` |
| API key | 调用某项服务时使用的凭据。需要保密的 key 不能放进纯前端，应由受控后端保存和使用 |
| 环境变量 | 操作系统或运行环境提供给程序的配置值。Node 中常见 `process.env`；`.env` 文件需要显式加载 |
| XSS / 注入 | 不可信内容被当成代码或命令执行的一类问题。普通文本用 `textContent`，数据库查询使用参数化等方式 |

## 工程习惯

| 术语 | 在这里指什么 |
| --- | --- |
| 重构（Refactor） | 在保持外部行为不变的前提下改善代码结构，重构后仍要运行验收 |
| 边界情况（Edge case） | 空值、零、负数、超长、重复、越界等需要单独决定行为的情况 |
| 回归（Regression） | 修改一个问题后，原本正常的功能出现问题。相关复测用于发现回归 |
| 纯函数（Pure function） | 同样输入总得到同样输出，且不直接修改外部状态的函数，通常容易单独测试 |
| 断言（Assertion） | 测试中写下的预期判断，例如 `assert.equal(formatTime(60), '01:00')` |
| MVP（最小可行产品） | 能验证核心价值的最小产品版本。可运行原型不一定已经能验证真实需求 |
| 规格驱动（Spec-driven） | 先写需求与完成标准，再按规格实现和验收。本指南使用 `REQUIREMENT.md` 与 `TODO.md` 实践这一过程 |
| 404 | HTTP 状态码之一，表示请求地址没有对应资源。还要检查路径、大小写、部署配置和接口路由 |
| Issue | 项目里的任务、问题或讨论记录。参与开源项目前先读 issue 和贡献指南 |
| PR（Pull Request） | 请项目维护者审查并合并改动的请求。小改动也要说明动机、范围和验证结果 |
| Vibe coding | Karpathy 提出的原始用法，强调快速接受 AI 输出、暂不细读代码，适合低风险试验 |
| Vibe engineering | Simon Willison 讨论过的对照说法，强调使用 AI 时仍保留审查、测试、文档和开发者责任。相关术语仍在演变 |
